# 테마 라이프사이클 — D0/리더 판정 서열 방식 백테스트 (v5.123)

## 배경

`theme_lifecycle.py`(v5.121~v5.122)는 D0(점화일) 판정과 rank1(리더) 결정에
그날 **거래대금(절대값) 순위**만 사용했다. 사용자 지시로 두 방식을 추가:

- **정적**: `theme_map.json`의 `stocks[i].rank` — ⚠️ **시총순이 아니다.**
  `theme_map.py`의 Claude 생성 프롬프트(34~35행)는 "사업 직결도가 높은
  순서로 rank를 매겨라(1=대장주)"를 요구한다. 즉 정적 rank = "이 테마와
  가장 직접 연결된 종목" 순위(Claude의 주관적 판단)이지, 시가총액 순위가
  아니다. 이 문서 작성 시점 기준 다른 어떤 곳에도 정적 rank를 "시총순"
  이라 명시한 문구가 있다면 그건 부정확한 서술이니 함께 정정할 것.
- **회전율**: 오늘 거래대금 ÷ 자기 트레일링 20거래일 평균 거래대금(당일
  제외). 시가총액 데이터는 이 코드베이스에서 종목당 별도의 느린 yfinance
  `.info()` 호출로만 얻을 수 있어(스캐너 화면에 이미 쓰이는 캐시성 계정
  데이터가 아님) 일별 시계열로 쓰기엔 비용이 커, 사용자가 제시한 대안(자기
  평균 대비 배수)을 채택.

## 백테스트 — 4개 실사이클, 어느 서열이 실제 점화 종목을 가장 잘 맞히나

"실제 점화 종목" = 그날 테마 구성종목 중 당일 수익률이 가장 높은 종목
(D0 판정 자체가 "rank1의 당일 +5%↑"을 요구하므로, 어느 서열의 rank1이
실제 최대상승 종목과 일치하는지가 그 서열의 리더 포착 정확도).

| 사이클 | D0 | 실제 최대상승 종목(수익률) | 정적 rank1 | 거래대금 rank1 | 회전율 rank1 |
|---|---|---|---|---|---|
| 제약·바이오 cycle1 | 2026-06-17 | **067290.KQ 존치신약** +29.87% | 207940.KS(오답) | 196170.KQ(오답) | **067290.KQ(정답, 배수 26.4x)** |
| 제약·바이오 cycle2 | 2026-08-26 | **326030.KS SK바이오팜** +8.53% | 207940.KS(오답) | 128940.KS(오답) | **326030.KS(정답, 배수 4.9x)** |
| 반도체 cycle1 | 2026-06-18 | **000660.KS SK하이닉스** +6.51% | 000660.KS(정답) | 000660.KS(정답) | 000660.KS(정답, 배수 1.35x) |
| 반도체 cycle2 | 2026-07-31 | **000660.KS SK하이닉스** +29.95% | 000660.KS(정답) | 000660.KS(정답) | 042700.KS(오답, 배수 2.21x) |

**스코어카드(4건 중 적중 수)**: 정적 2/4, 거래대금 2/4, **회전율 3/4**.

### 중요한 정정 — 이전 세션 보고와 다른 "known leader"

이전 v5.122 작업의 보고서는 제약·바이오 cycle1의 리더를 "알테오젠"
(196170.KQ, 거래대금 rank1)으로, cycle2를 "한미약품"(128940.KS, 거래대금
rank1)으로 기재했다. 이는 **기존 `_ignition_at()`가 거래대금 rank1만
"리더 후보"로 검사**했기 때문에 나온 값이지, 그날 실제로 가장 크게 오른
종목은 아니었다:
- cycle1 실제 최대상승은 **존치신약 +29.87%**(알테오젠은 +5.82%로
  "+5%↑" 문턱은 넘겼지만 존치신약의 절반도 안 됨). 존치신약은 거래대금
  절대값은 2위였지만 자기 평소 거래대금 대비 **26배** 튀어 회전율로는
  압도적 1위 — 이게 거래대금 서열이 놓치고 회전율 서열이 잡아낸 정확히
  그 사례다.
- cycle2 실제 최대상승은 **SK바이오팜 +8.53%**(한미약품은 +5.79%로 역시
  문턱은 넘겼지만 1위는 아니었음).

### 실패 사례 — 회전율도 만능은 아님

반도체 cycle2(2026-07-31)는 테마 8종목 전부가 +16~30% 동반 급등한 날
(개별 종목 이슈가 아니라 업종 전체 랠리). 이런 날엔 평소 거래대금이 작은
종목의 "배수"가 기계적으로 크게 튀어(042700.KS 배수 2.21x) 실제 최대
상승·최대 거래대금 종목(SK하이닉스, +29.95%, 정적·거래대금 둘 다 정답)을
회전율만 놓쳤다. 표본 n=4로는 이 실패모드가 얼마나 흔한지 확정할 수 없음
— "테마 전체 동반급등 날엔 회전율 서열의 신뢰도가 떨어질 수 있다"는
가설로만 기록.

## 채택

`LEADER_RANK_METHOD = "turnover_ratio"`(theme_lifecycle.py) — 4건 중 3건
적중으로 3방식 중 최고. n=4의 작은 표본이라 확정적 증거는 아니고, 특히
"테마 전체 동반급등" 상황에서의 약점이 알려진 채로 채택함을 명시. 정적/
거래대금 서열도 API 응답(`ticker_rank_today_static`/`ticker_rank_today`/
`ticker_rank_today_turnover_ratio`, D0 시점도 동일 접두사로 3종)에 계속
노출되어 참고 가능 — D0/리더 판정 로직 자체만 회전율로 전환됨(`_leader_ranked()`
가 유일한 판정 경로, `_ignition_at`/`assign_rank_groups`/`classify_phase`
전부 이 함수를 통해서만 리더를 읽는다).

## 검증

`compute_theme_series()`가 실제로 위 표의 4개 날짜에서 동일한 결과를
내는지 직접 호출로 재확인(수작업 재계산과 완전히 일치, `_leader_ranked()`
가 `ranked_turnover_ratio`를 정확히 참조하는 것도 확인). `find_cycles`/
`classify_phase`는 로직 자체를 안 건드렸고(리더 판정 소스만 교체) 회전율
전환 후에도 정상 실행됨을 스모크 테스트로 확인.

## 남은 것 (범위 밖, 이번 작업에서 처리 안 함)

- `static/index.html`의 라이프사이클 UI 서브뷰에 3종 서열을 나란히 표시
  하는 작업은 **하지 않음** — 동시에 다른 포크가 `static/index.html`을
  (theme_map POST 비동기 job 패턴 관련) 커밋 안 된 상태로 수정 중이라,
  같은 파일에 손대면 그 작업과 충돌할 위험이 있어 이번 작업 지시("do NOT
  touch/disturb those files")에 따라 보류함. API 응답에는 3종 전부 이미
  노출되므로, 그 포크의 작업이 커밋된 뒤 화면 표시만 추가하면 됨.
- "정적 rank = 시총순"이라는 오해가 사용자의 다른 요청(UI 툴팁 문서화)
  에도 전제로 깔려 있었다면, 그쪽도 이 문서의 정정 내용(사업직결도 순)
  으로 맞춰야 함 — 이번 작업 범위 밖이라 여기 기록만 남김.
