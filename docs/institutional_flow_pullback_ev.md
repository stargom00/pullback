# 기관/외국인 수급이 눌림목 EV를 개선하는가 (2026-08-25)

**결론: 기각.** 5개 후보 필드(기관 5일/20일, 외국인 5일/20일, 연속매수일수)
모두 눌림목 신호의 EV를 뚜렷하고 견고하게 개선하지 못했다. 사전에 정한
기준을 통과한 필드가 하나(`inst_20d`) 있었지만, 통계적 유의성 재확인에서
잡음과 구분되지 않는 것으로 드러나 최종적으로 함께 기각했다. **UI 반영
없음** — scanner.py/app.py/static 전부 무수정.

## 데이터 소스 — pykrx 대신 네이버 스크래핑을 쓴 이유 (진단 완료)

사용자 요청대로 pykrx 실패 원인을 먼저 진단했다:

1. **실제 에러**: `pykrx.stock.get_market_trading_value_by_date()`를 직접
   호출하면 내부적으로 `data.krx.co.kr/comm/bldAttendant/getJsonData.cmd`에
   비로그인 GET을 보내고, 서버가 **HTTP 400 + 본문 `"LOGOUT"`**을 반환한다.
   JSON 파싱 실패("Expecting value: line 1 column 1")는 이 텍스트 응답을
   JSON으로 파싱하려다 난 증상일 뿐, 근본 원인은 인증 거부다.
2. **버전 확인**: 설치본 1.2.8 = PyPI 최신(직접 대조 확인) — stale 버전
   문제가 아니다. 오히려 이 버전 자체에 `KRX_ID`/`KRX_PW` 환경변수로
   로그인 세션을 구성하는 코드(`pykrx/website/comm/auth.py`)가 내장돼
   있다 — pykrx 관리자들도 이 로그인 요구를 인지하고 대응한 상태.
3. **네트워크 확인**: `curl`로 `data.krx.co.kr` 자체는 200 응답, 우리
   요청도 정상적으로 KRX 서버에 도달해 세션 쿠키(`JSESSIONID`,
   `__smVisitorID`)까지 발급받는다 — **IP 차단이 아니다.** 서버가
   정상적으로 응답하고 있고, 그 응답이 "로그인 안 했으니 거부"라는
   애플리케이션 레벨 판단일 뿐이다. 기본 OHLCV 통계 엔드포인트
   (MDCSTAT01701)로도 동일하게 재현돼 특정 API 하나만의 문제가 아니라
   **data.krx.co.kr JSON 통계 전체가 로그인 필수로 바뀐 것**으로 확인.

이 프로젝트는 이미 정확히 같은 벽을 겪은 전례가 있다(`universe.py`:
"pykrx는 KRX 로그인 요구로 폐기, v4.38.9") — 가격 데이터를 네이버
스크래핑(`naver_kr.py`)으로 이미 전환해 쓰고 있다. 계정 로그인 자격증명을
스크립트에 심는 건 이 프로젝트 범위 밖이라 채택하지 않고, 이번에도 같은
패턴(네이버 스크래핑)으로 대체했다 — 신규 공용 모듈
`scripts/measurements/investor_flow.py` (`naver_kr.py`의 헤더/재시도/지터
관례 재사용, scanner.py/app.py 무관).

데이터: `finance.naver.com/item/frgn.naver?code={6자리}&page={n}` —
페이지당 20거래일, 날짜별 종가·기관순매매**거래량**(주)·외국인순매매
**거래량**(주)·외국인보유주수·외국인보유율을 제공.

## 근사와 오차 캐비어트

**금액 근사**: 원화 순매수 금액이 아니라 "거래량"(주)만 주어지므로
`순매수 금액 ≈ 순매매거래량 × 그날 종가`로 근사했다(하루 전체 체결이
종가 1점에서 일어났다고 가정). 실측: KR 30종목 표본, 최근 250거래일
`|종가 - (고가+저가)/2| / 종가`(종가가 일중 대표가격에서 벗어난 정도의
근사 지표) 기준 **평균 1.20%, 중앙값 0.89%, p90 2.54%**(n=7,500
종목·일). 5일/20일 누적 시 개별 일자 오차가 부분 상쇄되긴 하지만, 완전한
상쇄를 보장하진 않으므로 이 필드들의 절대적 크기(%)는 참고용 근사치로
읽어야 한다 — 다만 이번 측정의 결론(상위/하위 반분 EV 비교, 사분위
단조성)은 **순위(rank) 기반**이라 종가 근사가 준 systematic bias보다
날짜별 무작위 편차에 더 민감하고, 그 무작위 편차는 5~20일 누적으로
상당 부분 상쇄된다 — 결론 자체를 뒤집을 정도의 오차는 아니라고 판단.

**시가총액 근사**: `외국인보유주수 / (외국인보유율/100)`로 상장주식수를
역산해 시총을 근사(외국인보유율 0%/비공개 종목은 정규화 필드 제외,
이번 표본에서는 발생하지 않음 — 636건 전부 정규화 성공).

## 방법론

- **눌림목 KR 히트**: `harness.py` + `scanner.analyze()`(CONFIG) 그대로
  호출, off=60~250 10간격 20지점(기존 캠페인들과 동일 표준), 저유동성
  하드필터(`harness.passes_liquidity_filter`) 통과분만. **대조군이
  따로 필요 없는 구조** — 이번 측정은 "히트 집합 내부"를 수급 필드로
  상위/하위 나눠 비교하는 것이라, 비교 대상 두 그룹 모두 이미 같은
  유동성 컷을 통과한 히트에서 나온다(README 규칙 6 자동 충족).
- **슈퍼대장 여부**: `analyze_super()`를 동일 시점 데이터로 직접 호출해
  `is_super` 부착 — app.py `run_scan()`의 실제 부착 로직(3946~3948행)과
  1:1 동일.
- **수급 필드**: 히트 종목만 골라 `investor_flow.py`로 스크래핑(전체
  유니버스 아님 — 비용 절감), signal_date 이하 데이터만 사용해 룩어헤드
  방지. `inst_5d`/`inst_20d`/`frgn_5d`/`frgn_20d`(시총 대비 % 누적
  순매수), `streak`(기관+외국인 합산 연속 순매수일수, signal_date부터
  역산).
- **판정 기준(사전 명시)**:
  - 상위/하위 반분 EV 격차 ≥ **+0.05R**이고 방향이 예상대로(수급
    높을수록 EV 높음)면 "채택후보"
  - 격차가 0.05R 미만이거나 역방향이면 "기각"
  - 채택후보는 4분위 EV로 재확인: Q1→Q4 인접 3구간 중 최소 2개가 기대
    방향과 일치하면 "대체로 단조" 통과, 아니면 비단조로 강등해 기각

### 재검토 — 통계적 유의성 (사전 기준에 없던 추가 확인)

사전 기준(격차+단조성)은 "우연"을 걸러내려는 의도였지만 임계값 자체가
표본 크기·분산을 반영하지 않아 느슨했다. `inst_20d` 반분(하위 n=316,
상위 n=316)의 표준오차를 승률·도달률로부터 역산해 z검정한 결과:

```
gap = +0.111R, SE(gap) ≈ 0.113R, z ≈ 0.99 (p ≈ 0.32, 양측)
```

**유의하지 않음.** n=632, 결과가 -1R/0R/+2R 세 값만 갖는 이산분포라
분산이 커서(각 그룹 표준오차 ~0.08R) 0.11R 격차는 순수 표집 잡음
범위 안에 있다. **`inst_20d`도 최종 기각**으로 판정을 뒤집는다 — 사전
기준을 기계적으로 통과했다고 그대로 채택하면 이번 캠페인이 막으려던
바로 그 "우연을 진짜 신호로 오인"하는 실수를 반복하는 것이기 때문.

### 슈퍼대장 필터와의 관계

- 수급 상위 절반(inst_20d 기준) 중 슈퍼대장 소속 비율: **14.9%**
  (n=316) — 전체 표본의 슈퍼대장 비율(16.3%, n=632)보다 오히려 낮다.
  즉 수급 상위와 슈퍼대장은 겹치지 않고, 약하게라도 음의 상관에
  가깝다 — 수급 필터가 슈퍼대장의 대체재나 부분집합이 아니라는 뜻(다만
  어차피 채택되지 않을 필드라 실익 없음).
- 슈퍼대장 소속만(n=103) 다시 inst_20d로 반분: 하위 EV -0.294R(n=51),
  상위 EV -0.135R(n=52), 격차 +0.160R — 표본이 작아(그룹당 n≈51) 신뢰
  구간이 넓고(SE(gap)≈0.26R, z≈0.62) 역시 유의하지 않음.

   시장 국면 차이로 벌어졌을 가능성이 커 보이지만, 검증하지 않았다.
2. **슈퍼대장 소속 서브셋 EV가 음수(-0.214R, n=103)**: GUIDE.md
   "슈퍼대장 활용법"(v5.83)에 인용한 +0.266R(Script A, 2026-08-08)과
