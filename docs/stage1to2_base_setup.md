## §1. 사전등록

### 1.1 동기 · 배경

2026-09-11 HIMX. 고점 대비 −40%, 200MA 근처 8주+ 횡보, ATR 수축, RS 낮음. 현 스캐너는
Stage 2 눌림(RS 80+, 200MA 위 상승 중)만 잡아 **이 유형을 설계상 배제**한다.
설계 원칙은 "같은 패턴보다 다양한 위치의 상승"이므로, 배제가 옳은지 한 번은 재봐야 한다.

**이 측정은 HIMX 1건을 검증하는 게 아니다.** HIMX는 조건을 눈으로 뽑아낸 출처일 뿐이고,
그 1건의 사후 성과는 판정에 쓰지 않는다(그 종목이 어떻게 됐든 무관). 판정은 90개
체크포인트 전수 시뮬레이션 결과로만 한다.

### 1.2 조건 후보 — 이게 탭 필터의 초안이다

**출처 고지(CLAUDE.md "새 CONFIG 조건·임계값 도입 시 출처 기록" 4번 유형):
아래 6개 숫자는 HIMX 한 건에서 사용자가 눈으로 잡은 임의값이다. 웹 검색·백테스트·
문헌 근거가 없다.** 이 측정이 그 임의값 한 세트를 그대로 검정하는 것이다.

| # | 조건 | 측정에서 쓸 정확한 정의 |
|---|---|---|
| 1 | 200MA 대비 −10% ~ +10% | `-0.10 ≤ close/ma200 − 1 ≤ +0.10` (ma200 = 종가 200봉 SMA) |
| 2 | 52주 고점 대비 −30% 이하 | `close ≤ max(High, 최근 252봉) × 0.70` |
| 3 | 최근 20거래일 고저 범위 ≤ 15% | `(max(High,20) − min(Low,20)) / min(Low,20) ≤ 0.15` |
| 4 | ATR(14) 20일 전 대비 ≤ 0.8배 | `ATR14(t) / ATR14(t−20) ≤ 0.80` (ATR는 scanner.py와 같은 계산) |
| 5 | 20일 평균 거래량 ≤ 60일 평균 | `mean(Volume,20) ≤ mean(Volume,60)` |
| 6 | RS 40~80 | `40 ≤ rs_rank < 80` — **80은 제외**(눌림목 `rs_min=80`과 겹치지 않게 하한 개방) |

- **격자탐색 금지.** 이 한 세트로만 잰다. 6개 조건 각각의 변형·조합을 여러 개 돌린 뒤
  잘 나오는 걸 고르면 과적합이다. **미달이어도 조건을 바꿔 다시 돌리지 않는다**(1.7).
- 추가 하드 요건: `min_bars = 210`(200MA·52주 계산에 필요, 전 탭 공통),
  `harness.passes_liquidity_filter()`(KR 3억/일·US $2M/일, price_frozen 제외),
  KR 시총 1000억 이상(`app._MCAP_MIN_EOK`, 1.5 참고).
- **6조건은 AND.** 순서는 판정에 무관하지만 진단용으로 조건별 생존 수를 기록한다
  (어느 조건이 실제로 거르는지는 서술이지 판정이 아니다).

### 1.3 대조군

| 군 | 정의 |
|---|---|
| **T (대상)** | 1.2의 6조건 전부 통과 |
| **C1 (눌림목)** | 같은 체크포인트의 `scanner.analyze()` 히트(프로덕션과 동일 경로) |
| **C2 (유니버스)** | 같은 체크포인트에서 min_bars·유동성·시총 필터를 통과한 **전 종목** |

- C1이 **판정 대조군**이다(1.6). C2는 "시장 자체가 그 시기에 얼마나 올랐나"를 보정하기
  위한 서술용 기준선으로, 판정 문턱에 쓰지 않는다.
- T와 C1은 RS 조건(40~80 vs ≥80)으로 **구조적으로 배타적**이다 — 같은 종목·같은
  체크포인트가 양쪽에 들어가는 일은 없다. 실행 시 assert로 확인한다.

- **진입·수익률 정의**: 체크포인트 당일 **종가 진입**, **20거래일 뒤 종가**까지 보유

  n / 수익률 중앙값 / 평균 / 승률(>0) / +10% 이상 비율 / −10% 이하 비율 / 표준편차.
- **룩어헤드 방어**: ① 조건 판정·RS·벤치마크는 전부 체크포인트까지 자른 데이터만 사용
  ② 미래 구간은 `harness.future_after()`로만 접근 ③ 유니버스는 앵커 고정(1.5)
  ④ 실행 시 assert: 자른 df의 마지막 날짜 ≤ 체크포인트 날짜, 미래 df의 첫 날짜 > 체크포인트 날짜.
- **실행 시각 스탬프**: 결과 JSON에 `harness.run_stamp()` 필수(CLAUDE.md 90cp 실행
  시각 규칙). **주말(KR·US 양 시장 휴장)에 실행한다** — 2026-09-13은 일요일이라
  마지막 봉이 양 시장 모두 09-11(금)로 확정돼 있어 장중·개장 전 앵커 문제가 원천적으로
  없다(§3-5). 실행이 평일로 넘어가면 KST 16:00~22:30 창을 지킨다.
- **자기검증 게이트(R0 대체)**: 신규 측정이라 복제할 원본이 없으므로, **C1(눌림목)

### 1.6 판정 (재량 판단 금지)

**기준선은 C1(눌림목)이다.** 아래 네 조건을 **전부** 만족해야 통과:

1. **효과 크기**: T의 20일 수익률 **중앙값** − C1의 중앙값 **≥ +1.0%p**
2. **유의성**: **독립 2표본 Mann-Whitney U 정규근사 z ≥ 1.96**(대응표본 아님 — T와 C1은
   서로 다른 종목 집합이다). `harness.mannwhitney_zscore()` 신설(2026-09-13).
3. **시기 반분 재현**: 체크포인트를 전반/후반으로 나눠 **둘 다** 중앙값 차이 ≥ +1.0%p
4. **표본**: **각 시장 n ≥ 100**(KR·US 각각의 T 히트 수)

**1·2 모두 중앙값(순위) 기준으로 통일한다**(§3-2 확정). 효과 크기도 유의성도 분포의
위치를 보는 같은 것을 재므로 "중앙값은 벌어졌는데 평균이 끌어내려 미달" 같은 불일치가
생기지 않는다. 평균 차이와 Welch z는 §2에 **참고 기록만** 하고 **판정에 쓰지 않는다.**

**판정 범위**: 1·2·3은 **KR+US 통합 표본**으로 계산하고, 4(n ≥ 100)만 시장별로 본다
(§3-3). 시장별 중앙값차·z·승률은 §2에 서술로 남긴다 — 한쪽 시장에서만 성립하는
경우에도 **통합 판정 결과를 뒤집지 않는다.**

- **통과 → 탭 신설 "사전등록" 후보로 기록만 한다.** 실제 탭 신설·코드 변경은
  **별도 사전등록**이다. 이번 범위에서 scanner.py·app.py·static/index.html은 건드리지 않는다.
- **미달 → 현행 배제 유지.** 조건을 고쳐 재측정하려면 **별도 사전등록**이다
  (사후 조건 조정 금지 — 이 문서에서 파생된 재측정은 "이미 본 결과에 맞춘 조정"임을
  그 사전등록에 명시해야 한다).
- C2(유니버스) 대비 결과는 **서술**로만 기록한다. "C1엔 못 미쳤지만 C2보단 낫다"는
  통과 근거가 아니다.

## §3. 설계 판단 기록 (2026-09-13 확정 — "앞서 준 스펙 그대로")

아래 5건은 초안 단계에서 제기한 쟁점이며 **사용자 답변으로 전부 닫혔다. 실행 후
재해석하지 않는다.**

### 3-1. "R0 게이트 적용"은 이 측정에 적용할 대상이 없다 → 대체 게이트로 확정

R0 재현 게이트는 **원본 실행이 존재하는 재검증**에서 "원본 코드 그대로 돌려 히트 수가
±2% 안에 재현되는가"를 보는 장치다. 이번은 **신규 측정이라 복제할 원본이 없다.**

**확정(사용자 답변): 대조군 자기검증 게이트 ±5%. 룩어헤드 assert는 별개로 그대로 둔다
— 게이트가 assert를 대신하지 않는다.**

내용 — **C1(눌림목) 히트 수를 기존 90cp 측정과 대조하는 자기검증 게이트**:

- 같은 체크포인트 집합·같은 앵커 방식으로 뽑은 눌림목 히트 수가, 최근 90cp 측정
  (예: `2026-09-12_stall_exit_bench_revalidation` R1의 눌림목 히트 수)과 **±5% 이내**인지.
- 벗어나면 파이프라인이 뭔가 다르게 도는 것이므로 **멈추고 원인 보고**(결과 판정 전).
- ±2%가 아니라 ±5%인 이유: 유니버스 앵커 날짜가 다르고(09-13 vs 09-02) 그 사이
  유니버스가 실제로 바뀌었다 — 앞선 재검증들이 ±2%를 쓴 건 같은 날짜를 복제하려던 것이었다.

게이트 실패 시 판정 전에 멈추고 원인 보고(1.4에 반영).

### 3-2. 중앙값 문턱 + 평균 기반 z의 불일치 → (A) 중앙값으로 통일 확정

지시하신 판정은 **중앙값 차이 ≥ +1%p & 독립 2표본 z ≥ 1.96**인데, 하네스의
`welch_zscore()`는 **평균** 차이를 검정한다. 수익률 분포는 오른쪽 꼬리가 길어
평균과 중앙값이 상당히 갈린다 — **효과 크기는 중앙값으로 재고 유의성은 평균으로 재면
"중앙값은 +1.2%p 벌어졌는데 z는 평균이 끌려가 통과/미통과"가 실제로 생길 수 있다.**

선택지:

| 안 | 내용 | 비고 |
|---|---|---|
| **(A) 중앙값으로 통일** | Mann-Whitney U 정규근사 z(= 순위합 검정)로 유의성 판정 | 효과 크기·유의성이 같은 것(분포 위치)을 본다. 하네스에 신설 필요(`scipy` 미사용, 직접 구현). |
| (B) 평균으로 통일 | 효과 크기도 평균 차이 ≥ +1.0%p, z는 `welch_zscore()` | 기존 하네스 그대로. 단 꼬리 한두 건이 판정을 흔든다. |
| (C) 둘 다 요구 | 중앙값 차이 ≥ +1%p **AND** Welch z ≥ 1.96 | 가장 보수적. 지시 문구에 가장 가깝지만 통과 문턱이 실질적으로 높아진다. |

**확정(사용자 답변): (A) 중앙값으로 통일. Mann-Whitney U를 하네스에 신설한다.**
효과 크기 = 중앙값 차이 ≥ +1.0%p, 유의성 = MWU 정규근사 z ≥ 1.96 — **둘 다 중앙값(순위)
기준.** 평균 차이와 Welch z는 §2에 참고로 기록만 하고 판정에 쓰지 않는다.

**`harness.mannwhitney_zscore(a, b)` 구현 사양**(2026-09-13 신설, scipy 미사용):
- 두 표본을 합쳐 순위를 매기고 **동점은 평균 순위**(tie-corrected). U = R_a − n_a(n_a+1)/2.
- 기대값 μ = n_a·n_b/2, 분산은 **동점 보정식** 적용:
  `σ² = n_a·n_b/12 × [(N+1) − Σ(t³−t)/(N(N−1))]` (t = 각 동점군 크기).
- z = (U − μ)/σ, **연속성 보정 없음**(표본이 수천 단위라 영향 무시 가능, 일관성 위해 미적용).
- 부호: **z > 0 = T가 C1보다 큰 쪽**으로 맞춘다(판정 방향과 일치하게).
- σ = 0(전 표본 동일값)이면 `None` 반환 → 판정은 미달 처리.
- **검증**: scipy가 설치된 환경에서 `scipy.stats.mannwhitneyu(..., method="asymptotic")`와
  대조하는 단위 테스트를 붙이고(scipy 없으면 skip), 동점 다수 케이스를 포함한다.

### 3-3. 판정을 시장 통합으로 할지 시장별로 할지

**확정(사용자 답변): 판정은 KR+US 통합**(효과 크기·MWU z·시기 반분 전부),
**n ≥ 100 요건만 시장별.** 시장별 수치는 §2에 서술로 남기되 통합 판정을 뒤집지 않는다.

### 3-4. 이미 존재하는 "추세전환" 탭과 개념이 겹친다 → 겹침률 기록 + 후속 분기 사전 고정

`scanner.TURN_CONFIG`(추세전환 탭)의 주석에 **"1→2단계 첫 돌파 신호"**가 이미 있다:
`rs_min=70`, `max_ma200_dist=0.35`, `ma200_rising_min=-0.03`(200MA 기울기 평탄~막 드는
구간 허용), `first_base_only=True`.

차이는 **시점**이다 — 추세전환은 정배열(20>60>200 & 종가>200MA)이 **이미 형성된 뒤**
첫 베이스를 잡고, 이번 후보는 **전환 전 횡보**(200MA ±10%, ATR 수축)를 잡는다.
따라서 배타적이지는 않지만 겹칠 수 있다.

**확정(사용자 답변): 겹침률을 서술로 기록하고, 후속 방향을 결과 보기 전에 갈라둔다.**
추세전환 히트는 **대조군이 아니다**(대조군은 눌림목·유니버스 2개) — 겹침률 계산에만 쓴다.

- **겹침률 정의**: `|T ∩ TURN| / |T|` — 같은 체크포인트·같은 티커가 양쪽에 다 있는 비율.
  분모는 T(대상)다.
- **후속 분기 (1.6의 판정을 통과했을 때만 적용)**:

| 겹침률 | 통과 시 후속 |
|---|---|
| **≥ 50%** | "**추세전환 탭 조건 완화**" 별도 사전등록 — 새 탭이 아니라 기존 탭이 못 잡는 영역을 넓히는 문제로 본다 |
| **< 50%** | "**새 탭 신설**" 별도 사전등록 — 기존 탭과 다른 종목군을 잡는다는 뜻 |

- **50%는 임의값이다.** 근거 측정·문헌 없이 "절반"이라는 직관으로 정한 경계다
  (CLAUDE.md 출처 기록 원칙 4번 유형). 겹침률이 45~55%로 경계에 붙으면 그 사실 자체를
  §2에 적고 후속 사전등록에서 다시 판단한다.
- **미달(기각) 시에는 겹침률과 무관하게 후속 없음** — 현행 배제 유지.

### 3-5. 실행 시각 → 주말 확정

**확정(사용자 답변): 주말 실행.** 양 시장 휴장이라 마지막 봉이 09-11(금)로 확정돼 있고,
10번 건(장중 15:33 실행 → 재현 불가 종결)과 같은 사고가 구조적으로 불가능하다.

**NZST 시계 함정 규칙 적용**: 이 머신 시계는 NZST(UTC+12) = KST + 3h다. 파일 mtime과
`datetime.now()`는 전부 NZST이므로 **결과 JSON의 `run_stamp`에 KST를 같이 기록**하고
(`harness.run_stamp()`가 `run_at_local`·`run_at_kst`·`local_tz_utc_offset_hours`를 다 남긴다),
이 문서 §2에도 **KST로 적는다.** 주말이라 시각 자체는 판정에 영향이 없지만, 다음 재검증이
파일만 보고 앵커를 잡을 수 있게 하기 위한 것이다.
