## a) 문제의 코드 — 90cp.py의 entry 정의

`scripts/measurements/2026-09-04_kr_confirm_entry_all_tabs_90cp.py`
(KR 확인진입 5탭 재검증의 근거 스크립트, `docs/kr_us_strategy_map.md`
"KR 확인진입 5탭 재검증"/"⑤ base_vol50 정의 통일" 절이 인용하는 EV의
원본):

```python
# L163-197
def find_confirm_close(h, k_max=CONFIRM_K_MAX):
    ...
    fut = h["future"]
    trigger = h["signal_high"]          # L181 — 피벗 = 신호일 고가
    base_vol = h["trailing50_vol"]
    avail = min(k_max, len(fut))
    for k in range(1, avail + 1):
        ...
        c = float(fut["Close"].iloc[k - 1])
        vv = float(fut["Volume"].iloc[k - 1])
        if c > trigger and base_vol > 0 and vv >= CONFIRM_VOL_MULT * base_vol:
            return k, trigger            # L196 — "확인일 실제 종가(c)"가
                                          # 아니라 "trigger"(피벗)를 반환
    return None

# L203-219 run_confirm_analysis()
def run_confirm_analysis(hit_list, stop_key):
    ...
    for h in hit_list:
        ...
        conf = find_confirm_close(h)
        ...
        k, trigger_price = conf
        ...
        stop_val = h[stop_key]
        c_out = harness.race(trigger_price, stop_val, fut_after)   # L217
        #                     ^^^^^^^^^^^^ 레이스 진입가 = 피벗
```

**확인조건("종가 > 신호일 고가 + 거래량 배수")은 확인일 실제 종가를
쓰지만, 그 확인을 통과했다고 판정된 순간 레이스에 넘기는 진입가는
그 종가가 아니라 애초의 피벗(`trigger`) 값이다.** 즉 "종가가 신호일
고가를 넘었다는 걸 확인했다"는 정보를 손절/목표 계산 시점엔 쓰지 않고,
마치 그 피벗가에 지정가로 체결된 것처럼 레이스를 돌린다 — 확인
시점(거래일 종료 후에나 알 수 있는 정보)과 체결 가정(장중 그 가격에
살 수 있었다는 가정)이 서로 다른 시점의 정보를 섞어 쓰는 룩어헤드성
아티팩트다.

`2026-09-04_confirm_entry_grid_search_5tabs.py`도 동일 패턴(L186-190,
자체 docstring이 "진입가는 threshold 자체로 고정(확인일 실제 종가
아님)"이라고 명시)이고, `2026-09-04_long_box_ev_stage2.py`도 동일
(L292-293, `harness.race(trigger_price, ...)`).

## c) 8/8 0.796R과 v5.141 1.062R — entry 정의 확인

### 0.796R (2026-08-08)

`docs/imminent_stop_entry_investigation.md`의 원측정. 스크립트 파일이
남아있지 않다(harness.py 표준화 이전, README 감사에서 "재현 불가"로
기록됨). 다만 문서 본문이 정의를 직접 명시한다:

> "안C의 가치는 ... **'진입가를 신호일 고가로 정의한 것'** ... 같은
> 가격 공식에 있지 않다."

즉 이 수치도 진입가=신호일 고가(피벗)라는 동일 가정 위에 있었다 —
같은 문제군.

### 1.062R (2026-09-01, v5.141)

근거 스크립트: `scripts/measurements/2026-09-01_confirm_entry_90cp_revalidation.py`.
`run_imminent_variant()`(L159-192)가 이 수치를 포함해 v5.141의 표
(원 정의 0.658R / Close 조건 1.062R / Close+구조적stop 0.802R) 전부를
산출한다:

```python
# L165-184
def run_imminent_variant(im_hits, use_high: bool, stop_key: str):
    ...
    finder = find_confirm_high if use_high else find_confirm_close
    for h in im_hits:
        ...
        conf = finder(h)
        ...
        if use_high:
            k, trigger_price = conf
        else:
            k, trigger_price, _close_price = conf   # L178 — close_price를
                                                      # 받아놓고 버린다(_)
        ...
        stop_val = h[stop_key]
        c_out = harness.race(trigger_price, stop_val, fut_after)   # L182
        #                     ^^^^^^^^^^^^ 여기도 피벗
```

**핵심 발견**: `find_confirm_close()`(L101-112, Close 조건 판정용)는
이미 `close_price`(확인일 실제 종가, L111 `return k, trigger, c`)를
반환하고 있었는데, `run_imminent_variant()`가 그 값을 `_close_price`로
받아 **명시적으로 버리고**(밑줄 변수명) `trigger_price`만 레이스에
쓴다. "Close 기준으로 확인했다"는 게 "확인 조건"에만 반영되고 "진입
가격"에는 반영이 안 된 것 — a) 절과 완전히 동일한 패턴이 v5.141에도
이미 있었다.

**부수 발견 — 이미 존재했던 대조군이 안 쓰였다**: 같은 파일의
`run_pullback()`(눌림목 안C' 계산, L130-156)은 이미 `d_out = harness.
race(close_price, ...)`(L144)로 **종가진입 대조군을 계산해 결과 JSON에
저장**(`안D'_진입분(시점매칭 대조군)`)까지 해뒀었다:

```
$ python3 -c "..." 2026-09-01_confirm_entry_90cp_revalidation.results.json
"안C'_진입분": {"ev_R": 0.8486739469578783, "nv": 1282},     # 피벗진입(공식 인용치 0.849R)
"안D'_진입분(시점매칭 대조군)": {"ev_R": 0.1348402182385035, "nv": 1283},  # 종가진입(대조군, 미인용)
```

**눌림목의 종가진입 EV(0.135R)는 2026-09-01 당시 이미 계산까지 끝나
JSON에 저장돼 있었는데, 어느 문서에도 인용되지 않고 묻혀 있었다** —
오늘 `_entry_close` 재측정치(0.170R, 재fetch 드리프트로 소폭 차이)와
같은 자릿수. 이 문제는 새로 생긴 게 아니라 처음부터 데이터에 있었고,
"대조군" 칼럼을 만들어놓고도 아무도 그 숫자를 보지 않았다.

## d) 실제 KR 진입 4건 — 접근 불가, 데이터 필요

**이 항목은 완성하지 못했다.** 저널(`journal_user.json`)은 Railway
영구 볼륨(`/data`)에만 있고, 이 로컬 체크아웃에는 사본이 없다. 라이브
API(`pullback2-production.up.railway.app`)는 세션 쿠키 로그인이
필요한 401 응답만 반환하며(`app.py` L4588 `{"ok": false, "error":
"로그인 필요"}`), 로그인 자격 증명을 이 세션이 대신 입력하는 건
안전 정책상 하지 않는다.

**진행하려면 다음 중 하나가 필요하다**:
1. 사용자가 저널에서 확인(entered)된 KR 5탭 히트 4건의 `ticker/tab/
   entered_at(날짜)/entry(체결가)`를 직접 붙여주면, 그 티커·날짜로
   로컬에서 OHLCV를 다시 조회해 그 시점의 피벗(신호일 고가)/확인일
   종가를 역산해 비교표를 채운다.
2. 또는 `GET /api/debug/{ticker}` 같은 기존 디버그 엔드포인트 출력을
   사용자가 브라우저에서 직접 열어 붙여주면 같은 방식으로 처리한다.

데이터가 오면 이 절만 후속 커밋으로 채운다 — 이 문서의 나머지 결론
(e/f/g)은 이 항목 없이도 90개 체크포인트 집계 통계로 완결돼 있어
독립적으로 유효하다.

## e) 안D(buy-stop) · 안C'(종가진입+확인일저가손절) — 결과 및 설계

### 사전등록

- **안D(피벗 buy-stop 체결)**: 신호 후 최대 3거래일 내 **첫 고가 ≥
  피벗인 날 = 체결일**, 진입가 = 피벗(buy-stop 주문 가정, 지정가가
  아니라 "그 가격 도달 시 즉시 체결"). 거래량·종가 조건 없음(체결
  시점엔 아직 모르는 정보). **체결일 저가 ≤ 손절이면 그날 바로 손절
  처리**(장중 순서를 알 수 없어 보수적으로 손절 우선 가정) —
  `harness.race()`가 진입일 자체를 0번째 레이스 봉으로 받으면 저가
  ≤손절 우선판정이 이미 구현돼 있어 별도 코드 불필요. 레이스는
  체결일부터. **가짜 돌파(체결은 됐는데 그날 종가가 다시 피벗 밑으로
  마감) 포함** — 종가 조건 자체가 없으므로 자동 포함.
- **안C'(종가진입 + 확인일저가손절)**: 진입가는 안C와 동일(확인일
  실제 종가). 손절만 신호일저가/구조적stop 대신 **확인일(그날) 저가**
  로 당김 — 리스크폭이 좁아지면 R 단위 EV가 개선되는지 확인하는
  대안 가설(안D가 실패했을 때의 대비, 주 가설 아님).
- 채택 기준(공통): EV≥+0.15R & z≥1.96 & 시기반분(전/후반) 재현.
  안D를 주 가설로 판정, dedup z(티커별 최초 확인만 1건) 병기.

근거 스크립트:
`2026-09-04_kr_confirm_entry_all_tabs_90cp_entry_buystop.py`.

## f) 결론

실행 가능한 진입 정의 4종(안C_피벗[비교대상, 실행불가능], 안C_종가,
안D_buystop, 안C'_종가+확인일저가) 중 **사전등록 채택 기준을 통과한
조합은 단 하나** — **돌파임박, 종가진입, 신호일저가 손절(안C 원 정의
그대로): KR EV+0.157R, z=2.37, 시기반분 재현.** 나머지 4탭×3정의
조합(눌림목/박스돌파/돌파/추세전환 × 종가진입/buystop/안C')은 전부
z 미달이거나 시기반분 재현 실패다.

**KR에서 현재 검증된 진입법은 셋뿐이다**:
1. 종가베팅(`docs/kr_jongga_betting_backtest.md`, 이번 조사와 무관하게
   독립 검증됨)
2. 재점화 buy-stop(`docs/kr_theme_leader_reignition.md`, 0.755R —
   진입가=재점화일 고가지만 확인조건 자체가 **장중 고가 터치**라
   "확인 대기 비용" 문제가 원천적으로 없음, 안D와는 다른 메커니즘)
3. 돌파임박 종가진입(위 0.157R, 한계적 — 사전등록 기준을 스치듯

## g) 파급 — 같은 가정 위에 있던 다른 채택들

`docs/kr_us_strategy_map.md`의 다음 결정들도 전부 피벗진입 가정
(`harness.race(trigger_price, ...)`, `a)` 절 패턴)으로 측정됐으므로
**무효**다:

- **확인조건 격자탐색(vol_mult×margin, 2026-09-04)** — 돌파 vol_mult
  1.5→3.0배 채택, 눌림목 2.0배 강한확인 배지 EV(0.798→1.000R) 전부
  `2026-09-04_confirm_entry_grid_search_5tabs.py`의 `find_confirm()`
  (L187-190, docstring이 스스로 "진입가는 threshold 자체로 고정
  (확인일 실제 종가 아님)"이라고 명시)과 `combo_rows()`(L203-211,
  `harness.race(trigger_price, ...)`, L211)가 근거인데 둘 다 피벗진입
  (이미 v5.178에서 3.0배 원복, 배지 EV 문구 제거 완료 — `app.py`
  `CONFIRM_VOL_MULT_BY_TAB`).
- **250봉 장기 박스돌파 2단계 안C EV(0.256R)** — 이미 사전등록 기준
  미달로 미채택된 결론 자체는 안 바뀌지만, `2026-09-04_long_box_ev_
  stage2.py` L292-293도 동일하게 `harness.race(trigger_price, ...)`
  라 이 수치 역시 피벗진입 가정이었다 — 재측정하면(종가진입) 이
  0.256R보다 더 낮게 나올 것으로 예상되나, 이미 미채택 상태라 실무
  영향 없음(참고 기록만).

**재측정 원칙**: 앞으로 이 레포에서 confirm-entry 계열 EV를 다시 잴
때는 `run_*_analysis()`/`combo_rows()`류 함수가 `harness.race()`에
넘기는 첫 인자가 `trigger_price`(또는 `threshold`, `h["signal_high"]`
같은 피벗 파생값)인지 항상 먼저 확인한다 — 확인조건 자체가 종가
기준이어도 레이스 entry가 피벗이면 이 문서와 같은 아티팩트가 반복된다.
