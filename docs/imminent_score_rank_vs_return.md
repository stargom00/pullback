## §1. 사전등록

### 1.1 배경

2026-09-04 돌파임박 KR 히트 39종목을 사후 분석한 결과: score 1위(80.3) −9.4%,
2위 −5.7%, 7위 −20%, 29위 금강철강 +38.3%. score 순 정렬이 이후 수익률과
무관하거나 역상관일 수 있다. 하지만 n=39에 날짜 하나라 이것만으로는 판단할
수 없어서 90개 체크포인트(README 규칙9)로 잰다.

**방향 가설: 없음(양측).** 순상관, 역상관, 무상관 셋 다 열어 둔다.

### 1.2 정렬 기준 정의 — 무엇의 순위인가

- **주 측정 = `score` 단독 내림차순**(`analyze_imminent()` 반환 `score`, 동점은
  평균순위). 사용자 지시("score 순위(1=최고)") 그대로다.
- **참고: 실제 화면 순서는 `score` 단독이 아니다.** `app.py run_scan()`은
  `(triggered, score)` 내림차순으로 정렬한다(`triggered` = 피벗 대비 −2% 이내).
  이 순서의 ρ도 계산하지만 **참고로만** 보고하고 판정에는 쓰지 않는다. 사후에
  둘 중 유리한 쪽을 고르지 못하도록 판정 대상을 미리 하나로 고정해 둔다.
- **부호 규약**: 보고하는 ρ는 전부 **ρ(score 방향, 수익률)**이다. 순위(1=최고)를
  그대로 쓰면 부호가 뒤집히기 때문이다. **ρ>0이면 순상관**(score가 높을수록
  수익률이 높음), **ρ<0이면 역상관**이다.

### 1.3 대상 코호트

| 항목 | 정의 |
|---|---|
| 시장 | **KR만.** US는 측정하지 않는다(범위 밖). KR 단일 시장이라 규칙8은 해당 없음 |
| 체크포인트 | `harness.checkpoints(60, 950, 10)` = 90개 |
| 체크포인트 날짜 | **KOSPI 지수 캘린더 기준 날짜로 고정.** `cp_date = kospi.index[-(off+1)]`. 각 종목은 `df.loc[:cp_date]`로 자른다(아래 "하네스와 다른 점" 1번) |
| 유니버스 | `harness.fetch_universe_data(markets=("kr",), kr_days=1900, validate_offsets=OFFSETS)`, 즉 현재 `get_universe("kr")` |
| 시총 필터 | **프로덕션의 KR 시총 1000억 미만 제외(v4.91, `app._MCAP_MIN_EOK`)를 추정치로 재현한다**: `추정시총(cp) = 현재시총 × Close(cp) / 현재가`(naver 시총 API, 창 2 `recon.py`와 같은 방식). 현재 시총 정보가 없는 종목은 통과시킨다(fail-open, 프로덕션 `_get_mcap_allowed()`가 빈 목록일 때 통과시키는 것과 같은 방향). 하네스에는 이 필터가 없다. 기존 측정 전부가 이 필터 없이 쟀다는 뜻이기도 하다 |
| 벤치마크 | `harness.fetch_kr_benchmarks(days=1900)`(≈1275봉)을 날짜 기준으로 자른다. 기본값(900일)은 쓰지 않는다(1.8b) |
| RS | `harness.compute_rs_at_checkpoint()`. 체크포인트까지 자르고 정제한 df만 넣는다 |
| 데이터 정제 | 새로 만드는 `harness.clean_at_checkpoint()`, 즉 `app._filter_invalid_bars()`를 **체크포인트마다 자른 df에** 적용한다(1.7-6, 1.8a) |
| 히트 | `analyze_imminent(clean, rs_rank, rs_mom, cfg=IMMINENT_CONFIG, is_kr=True)` 통과 + `harness.passes_liquidity_filter()`(3억/일 미만 제외, price_frozen 제외) |
| 순위 분석 포함 조건 | 체크포인트당 KR 히트 **≥5개**. 5개 미만인 체크포인트는 순위 분석(ρ, 분위)에서 빼고 개수만 보고한다. **(AI 판단으로 정한 임의값. 5분위를 나누려면 최소 5개가 필요하다는 것 말고는 근거 없음. 사용자 승인 2026-09-11)** |

**하네스와 다른 점(README 규칙3 — 다르게 재는 이유를 남긴다):**

1. **날짜 기준 truncate.** `harness.truncate_at(df, off)`는 종목마다 "끝에서 off봉"을
   자른다. 그래서 거래정지나 무효봉 제거로 봉이 빠진 종목은 같은 체크포인트인데도
   다른 날짜로 잘린다. 이번 측정은 **같은 날 히트끼리 순위를 매기는 것**이 핵심이라
   날짜가 어긋나면 비교가 성립하지 않는다. `df.loc[:cp_date]`로 자르고,
   `trunc.index[-1] != cp_date`(그날 봉이 없음 = 정지)인 종목은 제외하고 개수를 센다.
   프로덕션은 이런 종목도 마지막 봉 그대로 스캔하므로 이 부분은 프로덕션과 다르다.
   제외 수를 보고한다.
2. **벤치마크도 날짜 기준.** `bench.loc[:cp_date]`로 자른다. `harness.bench_score_at()`의
   조용한 폴백(1.8b)은 쓰지 않는다.
3. **시총 필터 추가**(위 표).

### 1.4 측정

1. **5거래일 수익률**: `ret5 = close(T+5) / close(T) − 1`.
   - T = cp_date. `close(T)` = 히트의 `close`.
   - T+5 = **KOSPI 캘린더에서 cp_date 다음 5번째 거래일**. 그날 그 종목의 원본 Close를
     쓴다(무효 OHLC 행이라도 Close는 이월된 직전가라 그날 가격으로 유효).
   - 그 종목에 T+5 날짜의 행이 없으면 제외하고 개수를 보고한다. **제외율이 히트의
     2%를 넘으면 결과 해석 전에 따로 보고한다(AI 판단 임의값).**
2. **스피어만 ρ(score, ret5)**
   - **주 통계량(판정용) = 풀링 ρ**: 체크포인트마다 score 순위 백분위와 ret5 순위
     백분위를 따로 구하고(체크포인트 안에서만 순위를 매겨 시장 전체 등락을 제거),
     전체를 모아 피어슨 상관을 구한다. 순위끼리의 상관이므로 곧 풀링 스피어만이다.
   - 체크포인트별 ρ: 분포(평균, 중앙값, 양수 비율)와 **체크포인트 간 평균 ρ의
     t통계량**(체크포인트를 독립 단위로 본다)을 참고로 보고한다. 같은 날 히트는
     시장 충격을 같이 받아서 풀링 z(√n 기준)가 과대평가될 수 있기 때문이다.
     판정에는 쓰지 않는다.
3. **순위 5분위**: 체크포인트 안에서 `p = (rank − 0.5) / n`, 분위 = `floor(p × 5) + 1`
   (1 = score 상위 20%). 분위마다 **n, 평균, 중앙값, 승률(ret5>0), +10% 비율
   (ret5 ≥ +10%), −5% 비율(ret5 ≤ −5%)**을 계산한다.
4. **부수(참고만, 가설 아님)**: `late_level`(none / caution)별로 같은 지표를 보고하고,
   분위별 caution 비율도 보고한다. 09-04 사후 관찰(하위 19개 중 7개, 상위 19개 중 0개)에서
   나온 항목이라 판정도 후속 결정도 하지 않는다.
5. **참고**: 화면 순서 `(triggered, score)` 기준 풀링 ρ와 분위표(1.2).

### 1.5 판정 (주 통계량 = 풀링 ρ, score 단독)

위에서부터 순서대로 적용한다:

| 순서 | 조건 | 판정 |
|---|---|---|
| 0 | 앵커 게이트(1.6a) 실패, 유효성 게이트(1.6b) 실패, 또는 룩어헤드 assert(1.7) 실패 | **무효** → 원인 규명. ρ로 결론 내지 않음 |
| 1 | 5분위 중 하나라도 n < 100 | **판정불가**(표본 부족) |
| 2 | \|ρ\| < 0.10, **또는** 두 반기 ρ의 부호가 서로 다름 | **score 순위는 정렬 기준으로 무의미** |
| 3 | \|ρ\| ≥ 0.10 **그리고** 두 반기 ρ 부호가 전체와 같음 | **score 순위는 정보 있음** — ρ>0이면 순상관, ρ<0이면 역상관 |

- **시기반분** = OFFSETS를 정확히 반으로 나눈다. 최근 반기 = off 60~500(45개),
  이전 반기 = off 510~950(45개). 반기마다 풀링 ρ를 따로 구한다. "재현" = 두 반기 ρ의
  부호가 전체 ρ와 같음. 반기별 크기 하한은 두지 않는다(사용자 원문이 "부호 불일치"만
  실패 조건으로 정했음. 초안 확인사항에 별도 답이 없어 초안 정의를 유지).
- **0.10 근거(사용자 지시 원문)**: "n≈3500(90cp × ~39)에서 ρ=0.10이면 z≈5.9. 통계적으론
  충분하나 실용적 최소 효과로 잡음. 임의값이라는 것 명시." n≈3500은 09-04 하루로 추정한
  값이고, 실제 체크포인트당 히트 수는 실행해 봐야 안다.
- **분위당 n ≥ 100**: 사용자 지시 원문.

### 1.6 게이트

**(a) 앵커 게이트 — 파이프라인이 프로덕션을 재현하는가 (2026-09-04 1회 재구성)**

이 측정의 파이프라인(시총 필터, 정제, RS, analyze, 유동성)을 cp_date=2026-09-04에
그대로 돌려 프로덕션 기록과 대조한다. 앵커는 두 가지다:

- **앵커 A — 프로덕션 실제 히트 집합 39종목**: 프로덕션 `sector_snapshot.record_hits()`가
  daykey 2026-09-06(일요일. 주말 데이터 = 09-04 종가)에 기록한 KR 돌파임박 티커 집합.
  출처는 창 3의 `signal_snapshot_gg.json`/`sector_snapshot_gg.json`(2026-09-11 15:28 수신).
  이 39개는 창 2 `recon.py` 재구성 39개와 **정확히 같다**(2026-09-11 확인). 한계:
  `record_hits`는 '기타' 섹터 종목을 기록하지 않지만 재구성 39개 중 '기타'는 0개라
  이 차이는 없다. 순위와 score는 기록되지 않아서 **집합만** 대조할 수 있다.
- **앵커 B — signal_snapshot 09-04 최초감지 KR 돌파임박**: 사용자는 14개라고 했지만
  현재 파일(09-11 수신본)에서 `signal_date == 2026-09-04`인 KR 돌파임박은 **13개**다
  (나머지 1개는 이후 재감지로 signal_date가 갱신된 것으로 추정, 미확인). 13개 중
  12개가 앵커 A에 포함되고, 불일치 1개는 위드텍 348350.KQ(시총 경계 927억)다.
  앵커 B는 장중 최초감지가 섞여 있어 EOD 집합과 완전히 같지 않을 수 있으므로 앵커 A를
  주 게이트로 쓴다.
- 대조는 두 가지 유니버스로 한다:
  - **(a-1) 유니버스 = 09-04 EOD 파일**(`kr_universe_v6_1500_20260904_eod.json`):
    파이프라인 자체가 맞는지 보는 대조. **통과 기준: 앵커 A와의 Jaccard ≥ 0.90,
    그리고 앵커 B 중 앵커 A에도 있는 12개를 전부 포함.** 공통 종목의 score가 창 2
    재구성 score와 |차이| ≤ 0.1인 비율도 보고한다(RS 계산 경로가 달라서 생기는 차이 확인용).
  - **(a-2) 유니버스 = 현재 `get_universe("kr")`**(90cp 본 측정에 실제로 쓰는 유니버스):
    참고로만 보고한다. 유니버스가 달라서 생기는 차이의 크기를 보는 용도다.
- **0.90과 "12개 전부"는 AI 판단 임의값이다.** 창 2 재구성이 39/39로 일치했으니 같은
  데이터 경로면 1.0에 가까워야 한다. 다만 시총 추정의 경계 종목(±몇 개)은 허용하려고
  0.90으로 잡았다.
- a-1이 실패하면 90cp 본 실행을 하지 않는다(무효, 원인 규명).

**(b) 유효성 게이트 — 코호트를 제대로 재구성했는가 (90cp 전체)**

- **사용자 지시 원문**: "전체 히트 5일 수익률 중앙값이 유니버스 전체 5일 수익률
  중앙값과 ±3%p 넘게 벌어지면 코호트 재구성 오류 의심 → 무효, 원인 규명."
- **유니버스의 정의(규칙6 — 유동성 매칭)**: 각 체크포인트에서 cp_date 봉이 있고,
  정제 후 `len ≥ IMMINENT_CONFIG["min_bars"]`이며, 시총 필터를 통과하고,
  avg_turnover ≥ 3억원인 KR 전 종목의 (체크포인트, 종목) ret5를 모두 모은 것.
  avg_turnover는 히트와 같은 함수(`scanner.volume_info`)로 계산한다.
- 비교 = 히트 풀링 ret5 중앙값 − 유니버스 풀링 ret5 중앙값. 절댓값 > 3%p면 무효.
  참고로 체크포인트 가중을 같게 한 버전(체크포인트별 차이의 중앙값)도 보고한다.
  판정은 원문대로 풀링 값 하나로만 한다.
- 이 게이트는 큰 오류만 잡는다. 생존편향(1.9)은 히트와 대조군에 똑같이 들어가서 이
  게이트로는 안 잡힌다.

### 1.7 룩어헤드 방지 — assert (경고가 아니라 실패)

전부 `assert`로 구현한다. 하나라도 걸리면 스크립트가 중단되고 결과는 무효가 된다.

1. analyze와 RS에 들어가는 모든 df의 `index.max() == cp_date`.
2. `hit["close"] == round(clean["Close"].iloc[-1], 2)`.
3. RS 입력 `trunc_cache` 전체가 1번을 만족한다(RS 계산 직전에 검사).
4. `bench.loc[:cp_date]`의 마지막 날짜가 cp_date이고 길이가 253 이상. 253 미만이면
   **실패**다(0.0 폴백도, 전체 시계열 폴백도 하지 않음).
5. T+5 날짜 > cp_date이고, KOSPI 캘린더에서 정확히 5번째 거래일.
6. **정제는 truncate한 뒤에 한다.** `_filter_invalid_bars()` 갈래B(가장 최근 장기
   무효구간 이전을 전부 버림)를 전체 이력에 먼저 적용하면, 예를 들어 2025년에 장기
   정지된 종목이 2023년 체크포인트에서도 사라진다. 미래 사건으로 과거 표본을 고르는
   룩어헤드다. 그래서 `clean_at_checkpoint(df.loc[:cp_date])` 순서로 적용한다.
   실제로 효과가 있는지 보려고, "전체에 정제 후 truncate"와 결과가 다른
   (체크포인트, 종목) 건수를 진단값으로 보고한다.
7. 시총 추정은 `Close(cp)`(cp_date 종가)와 현재 시총/현재가의 비율만 쓴다. 현재 시총에는
   미래 정보(주식 수 변화)가 섞여 있다. 1.9에 한계로 적어 둔다.

### 1.8 harness.py 관련 결정

**(a) `_downcast()` 동기화 → 체크포인트 시점에서 한다(사용자 승인 2026-09-11)**

### 1.9 알려진 한계 (실행 전 선언)

- **생존편향**: 유니버스는 현재(2026-09-11) `get_universe("kr")`이고, KR 유니버스는
  거래대금 기준이다. 과거 체크포인트에는 "지금 거래대금 상위인 종목"만 들어가고,
  상장폐지 종목이나 그 뒤로 거래가 말라버린 종목은 빠진다. 히트와 대조군이 같은
  모집단이라 순위 상관에서는 1차적으로 상쇄되지만, 없어진다고 보장할 수는 없다.
  기존 90cp 측정 전부가 같은 한계를 갖고 있다.
- **시총 추정 오차**: 현재 주식 수를 과거에 그대로 쓴다(유상증자·자사주 소각 반영 안 됨).
  경계(1000억 부근) 종목에서 프로덕션과 어긋날 수 있다.
- **price_frozen 처리 차이**: 프로덕션은 price_frozen 종목을 "기본 숨김"만 하고 하네스는
  제외한다. 창 2 재구성의 09-04 39종목 중 price_frozen은 0개라(확인함) 앵커 대조에는
  영향이 없다. 90cp에서 제외된 수는 보고한다.
- 수정주가: naver는 현재 기준 수정주가를 준다. 수익률(비율)은 영향이 없다.
- 비용과 진입 규칙: 수익률만 본다. 진입이나 청산 규칙을 측정하는 게 아니므로 비용과 무관하다.

### 1.10 후속 (사용자 지시 원문, 미리 확정)

- 정보 있음(순상관): 현행 유지, 기록만 한다.
- 정보 있음(역상관): 정렬을 역순으로 바꾸는 건 별도로 사전등록한다. **이 측정 결과만으로 바꾸지 않는다.**
- 무의미: 정렬 대안 후보(late_level, vol_ratio 등) 탐색 측정을 별도로 사전등록한다.
  **이 측정에서 대안을 사후에 고르지 않는다**(1.4-4의 late_level 보고는 참고용일 뿐,
  후보 선정 근거로 인용하지 않는다).
- 판정불가 / 무효: 원인을 규명하고 보고한다. 기준을 바꿔서 재실행하려면 §1-부록에
  기록한 뒤에만 한다.
