## §1. 사전등록

### 1.1 대상과 배경

- **재검증 대상**: `scripts/measurements/2026-09-04_kr_confirm_entry_all_tabs_90cp_entry_close.py`
  (원래 결과: `docs/kr_us_strategy_map.md` "⑥ 종가진입 재측정",
  `docs/confirm_entry_lookahead_2026-09-04.md` b)절).
- **이 스크립트에 기대고 있는 현재 판정**: **"돌파임박 KR 종가진입 = 실행 가능한 KR 진입법
  3개 중 하나"**(EV +0.157R, z=2.37, 한계 통과). 나머지 4탭(눌림목/박스돌파/돌파/추세전환)은
  "확인진입 근거 없음".
- **재검증하는 이유**: 원래 스크립트는 `harness.fetch_kr_benchmarks()` 기본값(900일=601봉)을
  썼다. 그래서 90개 체크포인트 중 off 410~600은 벤치마크 점수가 0.0으로 폴백했고,
  off 610~950은 자르지 않은 전체 시계열(**룩어헤드**)을 썼다. 벤치마크 값이 틀리면 KS와
  KQ 사이의 RS 순위가 틀어져 히트 집합 자체가 바뀐다(`docs/kr_us_strategy_map.md` "사전 등록
  대기 — 벤치마크 룩어헤드 재검증" 절). 이 스크립트는 KR 전용 판정이라 오염을 전부 받는다.
- **판정의 여유가 얇다**: 원래 돌파임박 KR 셀은 z 2.37(문턱 1.96)이고, **EV는 전체
  0.157 / 초반 0.153 / 후반 0.162로 문턱 0.15를 0.003~0.012R 차이로 넘었다.** z보다 EV 쪽
  여유가 더 얇다.

### 1.2 원래 판정 기준 — 그대로 재적용한다(완화 금지)

원래 스크립트의 `judge()` / `half_split()`을 **import해서 그대로 호출한다**(재구현하지 않음.
글자 하나 바꾸지 않음). 탭별 KR 판정은 아래 조건을 **모두** 만족할 때만 "KR 유효"다:

1. `안C_종가진입` nv ≥ 100(`MIN_N_FOR_JUDGMENT`)
2. `안C_종가진입` EV ≥ +0.15R(`EV_GAP_THRESHOLD`. 이름은 gap이지만 원래 코드는 **절대 EV**에 적용)
3. z ≥ 1.96: `harness.ev_gap_zscore(안A_전체, 안C_종가진입)`, 즉 **안A(전 히트 즉시진입)
   대비 격차의 z**. 단일표본 z가 아니다
4. 시기반분: 원래 정의 그대로. `mid_off = OFFSETS[45]` = 510을 기준으로 **초반 = off ≤ 510
   (46개 체크포인트), 후반 = off > 510(44개)**. 반기마다 히트 ≥100이어야 계산하고, 두 반기
   모두 `안C_종가진입` EV ≥ 0.15R이어야 재현이다. 45/45로 정확히 반분하지 않는 원래의
   비대칭도 **그대로 둔다**.

확인조건(3거래일 내 종가 > 신호일 고가 + 거래량 ≥ base_vol50 × 1.5), 진입가(확인일 종가),
손절(돌파임박 = signal_low, 나머지 = 구조적 stop), 레이스(확인일 다음 봉부터 60봉) — 전부
원래 코드 그대로 쓴다.

**사용자 지시("원래 판정 기준(EV ≥ 0.15R & z ≥ 1.96 & 시기반분 & n ≥ 100) 그대로")와의
대응**: 위 1~4가 원래 코드의 정의이며, 사용자가 요약한 네 조건과 같다. 요약에서 드러나지
않던 세부(z가 안A 대비 격차 z라는 점, EV가 절대값이라는 점, 반분의 46/44 비대칭)는 원래
코드를 따른다.

### 1.4 실행 설계 — 네 번 돌리고 한 번에 한 가지씩만 바꾼다

fetch는 한 번 하고, 네 개 실행이 같은 데이터를 공유한다.

| 실행 | 정의 | 이 실행과 이전 실행의 차이가 보여주는 것 |
|---|---|---|
| **R0 원본 복제** | 원래 코드 그대로. 오염된 벤치마크 동작(900일 벤치마크 + `bench_score_at`의 조용한 폴백)을 **의도적으로 재현** | R0 − 원래(09-04 발표값) = **데이터 변동**(09-04 이후 naver 데이터 수정 등) |
| **R1 벤치마크만 수정** | R0에서 **벤치마크 계산 하나만** 교체 | R1 − R0 = **순수 벤치마크 오염 효과** |
| **R2 + 시총 필터** | R1 + KR 시총 1000억 필터(추정치) | R2 − R1 = **순수 시총 필터 효과** |
| R3 + 프로덕션 데이터 경로(참고) | R2 + 730일 창 + `harness.clean_at_checkpoint()` + 날짜 기준 종목 truncate + 레이스 구간의 무효봉 제거 | R3 − R2 = 데이터 경로 효과. **판정에 쓰지 않음** |

**R0을 같은 날짜로 맞추는 방법(원래 결과와의 차이를 최소화)**:
- 체크포인트 날짜를 원래 실행(2026-09-04 장 마감 후)과 **같게** 맞춘다. `Δ` = KOSPI 캘린더에서
  2026-09-04 이후 봉 수(실행일 기준으로 계산하고 assert)로 두고, 실제 offset = 원래 offset + Δ로
  돌린다. 결과에는 **원래 offset 라벨**(60~950)을 기록하므로 원래 `half_split()`이 그대로 작동한다.
- fetch 시작일도 원래와 같게 맞춘다. KR은 `kr_days = 1900 + Δd`, R0 벤치마크는
  `days = 900 + Δd`다(Δd = 실행일 − 2026-09-04 달력일수). 이렇게 하면 원래와 같은 과거 봉과
  같은 오염 패턴이 재현된다.
- 유니버스는 **2026-09-04 시점 `get_universe("kr")` 재현**을 쓴다(정적 `KR_UNIVERSE` + 
  `kr_universe_v6_1500_20260904_eod.json` + 워치리스트 KR). 원래 실행이 그날 저녁에 본
  유니버스다(직전 측정 앵커 a-1에서 이 구성이 09-04 프로덕션 히트를 39/39 재현했음).
  **R0~R3 전부 이 유니버스를 쓴다.**
- US는 다시 돌리지 않는다. 벤치마크 수정은 US에 영향이 없고(US는 벤치마크 차감을 생략.
  하네스 설계상 순위 불변), 원래 판정도 US를 판정 대상에서 뺐다. KR RS는 KR 종목끼리만
  순위를 매기므로(`compute_rs_at_checkpoint`) US를 빼도 KR 결과는 달라지지 않는다.

**시총 필터를 분리 실행(R2)하는 근거**:
- 고치는 이유: 이 셀이 떠받치는 판정은 **프로덕션 카드**("🔴 즉시행동 — 돌파임박 KR 종가진입")다.
  프로덕션은 시총 1000억 미만 KR 종목을 스캔하지 않는다(`app._MCAP_MIN_EOK`, v4.91). 이 필터가
  없는 측정은 프로덕션이 한 번도 보여주지 않는 종목까지 섞어서 잰 것이다. 직전 측정에서 이
  필터는 체크포인트당 약 274종목(유니버스의 약 20%)을 걸렀다. 무시할 수 있는 크기가 아니다.
- 분리하는 이유: R1에 합치면 사용자가 지적한 대로 "룩어헤드 효과"와 "필터 효과"가 섞인다.
  R1 − R0(벤치마크만)과 R2 − R1(필터만)을 따로 보고해야 "원래 통과가 벤치마크 오염 덕분이었는가"에
  답할 수 있다.
- 시총 추정 방식은 직전 측정(`docs/imminent_score_rank_vs_return.md` 1.3)과 같다.
  `현재시총 × Close(cp) / 현재가`로 추정하고, 시총 정보가 없으면 통과시킨다(fail-open).
  필터는 RS 계산 **전에** 적용한다(프로덕션 순서).

### 1.5 판정 유지 기준 (재량 판단 금지)

- **판정 실행 = R1과 R2 둘 다.** 돌파임박 KR 셀이 **R1과 R2 모두에서** 1.2의 네 조건을 전부
  통과해야만 **유지**한다.
- **R1 또는 R2 중 하나라도** 1.2의 조건을 하나라도 못 넘으면 **철회**한다(z < 1.96만이 아니라
  EV < 0.15, 어느 반기 EV < 0.15, nv < 100 모두 해당).
  - 사용자 지시 4번은 "z < 1.96이면 철회"라고 했다. 이것을 1번("원래 판정 기준 그대로")과 합쳐
    **원래 조건 중 하나라도 실패하면 철회**로 해석했다. z 조건만 보면 EV나 반기 조건이 실패해도
    유지되는, 원래보다 느슨한 기준이 되기 때문이다. **§3 확인사항 1.**
  - 두 실행을 모두 요구하는 이유: 결과를 본 뒤 통과한 쪽을 고르지 못하게 막는다. 둘 중 어느
    하나가 실패하면 그 결함 하나를 고친 것만으로 판정이 무너진다는 뜻이기 때문이다.
- R0과 R3는 판정에 쓰지 않는다(보고만).
- **나머지 4탭**: 원래 "무효"였던 탭이 R1/R2에서 "유효"로 나와도 **채택하지 않는다.** 새로
  채택하려면 별도로 사전등록해야 한다. 이 재검증은 기존 판정을 지키거나 철회하는 용도일 뿐
  새 판정을 만드는 용도가 아니다.

### 1.7 보고 형식

1. **5탭 × {원래(09-04 발표), R0, R1, R2, R3(참고)}** 표. 셀마다 `안C_종가진입` EV, z, nv,
   초반 EV(n), 후반 EV(n), 판정을 넣는다. **판정이 바뀐 셀은 표시**(✗→✓, ✓→✗).
2. **돌파임박 KR 셀의 변화 분해**(사용자 추가 지시): z와 EV 여유(EV − 0.15, 반기별 포함)가
   - 원래 → R0(데이터 변동)
   - R0 → R1(**벤치마크 오염 효과**)
   - R1 → R2(시총 필터 효과)
   에서 각각 얼마나 움직였는지 보고한다.
3. **해석 규칙(미리 정한 문장)**:
   - R0은 통과했는데 R1이 실패 → "**원래 통과는 벤치마크 오염 덕분이었다.**"
   - R1이 통과 → "**원래 통과는 벤치마크 오염과 무관하게 기준을 넘는다.**" 단 "효과가 실재한다"는
     표현은 쓰지 않는다. 문턱 근처의 단일 셀이고 다중비교는 보정하지 않았기 때문에, 기준 통과 이상의
     주장은 하지 않는다.
   - R0부터 실패 → "원래 통과는 오염을 재현한 조건에서도 재현되지 않는다(데이터 변동에 민감)."
     이 경우에도 판정은 R1/R2로 한다.
4. 진단값: R0 복제 정확도(탭별 KR 히트 수 / 확인 수를 원래 값 3449/8092/1074/1210/2353,
   확인 634/1271/388/448/381과 비교), 벤치마크가 폴백하던 체크포인트 수(R0), 시총 필터 탈락 수(R2),
   레이스 구간에 무효봉(OHLC ≤ 0)이 섞인 확인건 수(R1. R3가 이걸 제거했을 때의 영향을 해석하는 용도).

### 1.8 룩어헤드 방지 — assert

- R1~R3: 벤치마크를 `cp_date`까지 자른 뒤 `index[-1] == cp_date`이고 길이 ≥ 253인지 확인한다.
  아니면 실패.
- 전 실행: 확인 탐색은 원래 `find_confirm_close()`의 assert(k ≤ 3, 미래 봉 범위)를 그대로 쓴다.
  analyze에 넣는 df의 마지막 날짜가 해당 체크포인트 날짜인지(R3 한정) 확인한다.
- Δ 계산: 2026-09-04가 KOSPI 캘린더에 있는지, 그리고 `cal[-(60+Δ+1)]`이 원래 off 60의 날짜와
  같은지 assert.
- R0의 "오염 재현"은 **의도적**이다. 하네스 `bench_score_at()`은 이번에 assert를 넣어 고칠
  것이므로(1.10), R0은 스크립트 안에 **이전 동작의 사본**을 두고 "오염 재현 전용 — 사용 금지"라고
  주석을 단다. 판정 실행(R1/R2)은 이 사본을 호출하지 않는다는 것도 assert로 확인한다.

### 1.9 알려진 한계 (실행 전 선언)

- **유니버스 드리프트(못 고침)**: 2026-09-04 유니버스를 4년 전 체크포인트까지 그대로 쓴다.
  과거 각 시점의 거래대금 상위 유니버스는 재구성할 수 없다(EOD 유니버스 파일은 2026-09-01부터만
  있음). 직전 측정에서 5거래일 차이만으로도 히트 집합이 18% 어긋났다. 과거로 갈수록 이 차이는
  커진다. 원래 측정도 같은 한계를 갖고 있어서 **원래와 재검증의 비교는 공정하지만, 둘 다
  "프로덕션이 그날 보여줬을 목록"은 아니다.**
- 시총 추정 오차: 현재 주식 수를 과거에 그대로 쓴다.
- R0~R2는 원래의 **offset 기준 종목 truncate**(봉이 빠진 종목의 날짜 어긋남)와 **정제 없는

  벤치마크 효과만 분리하려고 일부러 남긴 것이다. 이 영향은 R3(참고)와 1.7-4 진단값으로만 본다.
- z 검정(`ev_gap_zscore`)은 안C가 안A의 부분집합인데도 두 그룹을 독립으로 가정한다. 원래 기준을
  그대로 쓰기 때문에 이 한계도 그대로 남는다.
- 슬리피지 0.3% 변형은 원래와 마찬가지로 참고로만 병기하고 판정에는 쓰지 않는다.
