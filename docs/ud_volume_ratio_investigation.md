# U/D Volume Ratio 재검증 (v5.57)

코텍(052330.KS) 리포트로 시작 — 우리 U/D 계산(0.92)이 MarketSmith 주봉 차트 U/D(2.0)와 2배 차이. "우리가 틀렸나?"에서 시작해 "다른 걸 재고 있었다"로, 최종적으로 "어느 쪽이든 실제 성과와 관계가 없거나 반대"로 결론이 이동한 조사 기록.

## 1. 계산 방식 자체는 표준과 일치

`up_down_volume(c, v, window=50)`: 최근 50일 중 종가>전일종가인 날의 거래량 합 ÷ 종가<전일종가인 날의 거래량 합. 웹 검색으로 확인한 IBD/MarketSmith 표준 정의(50 trading days, close vs prev close, up-day volume sum ÷ down-day volume sum)와 정확히 일치.

## 2. 코텍 격차의 원인 — 일봉 50개 vs "현재 보고 있는 차트 단위로 50개"

MarketSmith는 주봉 차트에서 U/D를 보여줄 때 "50 거래일"이 아니라 **"현재 차트 단위(주봉)로 50개 봉"**을 쓴다(Linnsoft UDVR 문서: "period가 보고 있는 차트 단위를 따라간다"). 코텍을 주봉으로 리샘플(종가=주 마지막, 거래량=주간 합)해 최근 50주로 계산하니 **정확히 2.00** — MarketSmith와 일치.

| 방식 | 값 |
|---|---|
| 일봉 50일(우리 현행) | 0.92 |
| 주봉 10주 | 1.56 |
| 주봉 20주 | 1.72 |
| **주봉 50주(MarketSmith)** | **2.00** |
| 일봉 10일 | 1.98 |
| 일봉 250일 | 1.35 |

전체 유니버스(n=3453) 확인 결과 일봉50일 vs 주봉50일 값이 **2배 이상 벌어지는 종목이 19.7%** — 코텍만의 특이 사례가 아니라 흔한 현상. 주봉이 일봉보다 큰 경우가 62%.

## 3. 성과 상관관계 — A(일봉50일)/B(주봉50주)/C(일봉250일) 전부 신뢰 불가

눌림목/돌파/돌파임박 3개 탭, 각 탭 자체 손절 기준 2R 레이스로 측정(off=60..250 step10, 전체 KR+US, n 265일 이상 데이터 확보된 히트만).

**이분법 EV(≥1.0 vs <1.0):**

| 탭 | A 일봉50일(현행) | B 주봉50주 | C 일봉250일 |
|---|---|---|---|
| 눌림목(n=1525) | 0.139 vs **0.330**(역) | 0.155 vs **0.287**(역, 완화만) | 0.161 vs 0.191(약한 역) |
| 돌파(n=209) | 0.190 vs 0.500(역, n=14) | **0.221** vs 0.071(정, n=14 노이즈 가능) | 0.189 vs 0.421(역, n=19) |
| 돌파임박(n=2795) | 0.229 vs **0.331**(역) | 0.244 vs 0.253(거의 0비트) | **0.251** vs 0.198(정) |

**결론**: 현행(A)은 3개 탭 모두 역방향(n 큰 눌림목·돌파임박에서 특히 뚜렷). 주봉(B)으로 바꿔도 눌림목은 여전히 역방향, 돌파임박은 그냥 0비트가 될 뿐 — "B가 A를 고쳐주지 않는다." 세 방식 중 어느 것도 "U/D 높음=좋은 성과"를 일관되게 지지하지 않음.

## 4. 반영 (v5.57)

### 카드 표시
- `s.ud_vol`/`s.ud` 배지 색상(초록=매집/주황=분산)을 방향성 암시 없는 중립색(`var(--muted)`)으로 통일. 툴팁을 "실측상 방향 불확실 — 판정에 안 씀, 참고용"으로.

### 추세전환 — 경고·점수 제거
- "📉 매집미확증" 배지, "⚠️ 매집 미확증... 관찰 권장" 경고 배너 삭제.
- `ud_weak` 필드 삭제(더 이상 계산 안 함).
- `score`에서 U/D 가감(±12점) 제거 — 배지만 빼고 점수는 남겨두면 몰래 계속 반영되는 상태라 같이 뺌. 배점 총합 125→115로 재정규화.

### 강한피벗(실험) — 하드 게이트 제거
`STRONG_PIVOT_MIN_UD`(ud<1.0이면 하드 제외) 게이트를 실측(아래 표) 후 제거. `strength_score`의 U/D 기반 `accum_score_component`(최대 20점)도 같은 이유로 제거 — 하드 게이트만 없애고 점수 성분을 남겨두면 최소컷(40점, pool 1개짜리만 해당)에서 계속 불리해지는 모순이 생기기 때문.

**측정** — 강한피벗의 1층(late_stage/ext200 하드컷)+저유동성 필터까지만 재현(Stage2/IBD9 풀 게이트는 매 체크포인트 전체 유니버스 재계산 비용이 너무 커서 이번 측정엔서 제외 — 실제 강한피벗보다 넓은 모집단, 결과 해석 시 감안):

| | n | 일평균 | EV | 대조군 EV |
|---|---|---|---|---|
| 게이트 있음(현행, ud≥1.0) | 1266 | 63.3 | 0.224 | 0.057 |
| 게이트 없음(전체) | 1587 | 79.35 | **0.252** | 0.043 |
| 새로 추가되는 것만(ud<1.0) | 321 | 16.05 | **0.361**(최고) | -0.013 |

게이트가 걸러내던 그룹이 EV 최고 — 게이트 제거로 히트 +25%, 전체 EV도 개선. 대조군 대비 우위는 게이트 유무와 무관하게 확인(강한피벗 자체의 엣지는 유효).

### 함수 중복 정리
`up_down_volume(c, v, window=50)`과 `ud_volume_ratio(c, v, days=50)`이 완전히 같은 계산(창 길이 파라미터 이름만 다름) — `up_down_volume`을 남기고 `ud_volume_ratio` 삭제, 호출부 4곳(scanner.py 3곳: `analyze_turnaround`/`analyze_ibd9_full` + app.py 1곳: `/api/debug`)을 전부 교체. `analyze()`(눌림목)는 원래 두 함수를 각각 한 번씩 불러 같은 50일 값을 두 번 계산하고 있어서 한 번만 계산하고 재사용하도록 같이 정리. `ud_volume_detail()`(상위1·3일 제외 분해, `ud_reliable` 판정)은 용도가 달라 유지.

## 5. U/D 전체 사용처 감사 (표시 / 점수 / 게이트)

`up_down_volume`/`ud_volume_detail`/`ud_vol`/`ud`/`ud_ratio` 등 U/D 계열 식별자를 scanner.py + app.py + static/index.html 전체에서 검색해 분류.

| 분류 | 위치 | 상태 |
|---|---|---|
| 표시만 | 카드 배지(7개 탭 `ud_vol`/`ud`) | ✅ v5.57 중립색 처리 |
| 표시만 | `ud_volume_detail`(ud_raw/top1_share/top3_share/ud_ex_top1/ud_ex_top3/ud_reliable) — 눌림목 "상위3일 제외" 표시 | 유지(방향 주장 없음, 순수 진단) |
| 표시만 | `/api/debug/{ticker}`의 `"ud"` | 유지(진단용) |
| 점수 | `trend_grade()` — ud≤0.8이면 등급 1단계 강등, ud≥1.5는 라벨만. 5개 탭(눌림목/돌파/박스돌파/돌파임박/패턴) grade 배지에 영향 | ⚠️ **미반영** — 아래 6번 참고 |
| 점수(제거됨) | `analyze_turnaround()` score ±12점 | ✅ v5.57 제거 |
| 점수 | `distribution_check()` — ud<1.0이면 "분산" 신호, caution/danger 레벨에 기여. `/api/dist/{ticker}`로 봇이 보유종목 하루 1회 체크해 danger 시 실제 알림 발송 | ⚠️ **미반영** — 다른 질문(보유 중 모니터링, 오늘 측정한 "진입 전 스크리닝"과 다름), 별도 측정 필요 |
| 점수 | `accumulation_score()`(급등매집 서브패턴, ud_vol 10% 가중 + trade_value_ratio 게이팅) | 조치 불필요 — 패턴 탭 전체가 이미 v5.50 "검증실패" |
| 점수 | `quiet_accumulation_score()`의 top1_share 컴포넌트(15/100점, 눌림목 `qa_score`/`qa_grade`) | 방향 미검증 — U/D 방향이 아니라 상승거래량 집중도라 다른 질문 |
| 점수 | IBD9 등급 변환(`analyze_ibd9_full`) — `score = 50*min(ud,3)/3 + ...`, ud가 점수 50% 차지 | 미측정 — IBD9는 이번 세션 백테스트 범위 밖 |
| 게이트(제거됨) | 강한피벗 `STRONG_PIVOT_MIN_UD`(ud<1.0 하드 제외) | ✅ v5.57 제거 |
| 게이트 | IBD9 `grade not in ("A","B")`면 제외 — grade가 ud 50% 반영이라 사실상 ud 하드게이트 효과 | 미반영 — IBD9 자체가 미측정 |
| 게이트(레포 밖) | 얼마냐봇 "눌림 지지 진입" 알림(`/api/pullback-signal/{ticker}`) — 봇이 U/D≥1.5를 하드 게이트로 판정(문서화됨) | **이 레포에서 수정 불가** — 봇 쪽 로직, 사용자에게 전달 필요 |

## 6. 미반영 — 다음 라운드 대상

### trend_grade() 8조건 실측 (v5.57에서 측정만, 재설계는 보류)

같은 3개 탭, ATR×2 대신 각 탭 자체 손절로 2R 레이스. 200일선 위/60일선 위/RS70+ 3개 조건은 각 탭 게이트가 이미 강제해 미통과=0건(0비트, 당연).

| 조건 | 눌림목(통과→미통과) | 돌파(통과→미통과) | 돌파임박(통과→미통과) |
|---|---|---|---|
| 200일선 상승 | 0.167→0.248(역) | 0.371→0.250(정, n작음) | 0.241→0.411(강한 역) |
| 60일선>200일선 | 0.177→0.154(약한 정) | 0.367→0.263(정) | 0.243→0.367(역) |
| 20일선 위 | 0.149→**0.251**(역) | 0비트 | **0.337**→0.128(강한 정) |
| 52주 저점+30%↑ | 0.178→0.145(약한 정) | 0.354→0.5(n=8 무시) | 0.249→0.203(약한 정) |
| 52주 고점-25%이내 | 0.164→**0.364**(강한 역) | 0.354→0.5(n=8 무시) | 0.247→0.259(거의 0비트) |
| U/D강등(ud≤0.8) | 0.167→**0.359**(강한 역) | 0.362→0.2(n=5 무시) | 0.248→0.232(거의 0비트) |

"20일선 위"는 눌림목·돌파임박에서 정반대 방향 — 탭마다 다르게 작동해서 단일 등급 산식에 같이 넣으면 안 되는 조건.

**등급(A/B/C/D)별 EV — 등급이 성과를 못 가름, 눌림목은 완전히 역순:**

| 등급 | 눌림목 | 돌파 | 돌파임박 |
|---|---|---|---|
| A | 0.140 | 0.315 | **0.354**(n=1211) |
| B | 0.196 | **0.500**(n=54) | 0.135(최악, n=1167) |
| C | 0.202 | 0.333 | 0.250 |
| D | **0.385**(n=26) | — | 0.239 |

눌림목: A등급 EV 최저, D등급 최고 — 완전히 역순. 돌파임박: A는 1등이지만 B가 C·D보다 나쁨 — 순서 안 맞음. 어느 탭도 A>B>C>D 순서가 안 나옴. **5개 탭(눌림목/돌파/박스돌파/돌파임박/패턴)에 노출되는 등급 배지가 현재 산식으로는 신뢰 불가** — 재설계 필요, 방향 확인 후 진행.

### 기타 미반영
- `distribution_check()`의 U/D 분산 신호(보유종목 알림) — 별도 측정 필요.
- `quiet_accumulation_score()`의 top1_share 컴포넌트 — 방향 미검증(다른 질문).
- IBD9의 U/D 의존(등급 변환 점수 50% + 사실상 게이트) — IBD9 자체가 이번 세션 측정 범위 밖.
- 얼마냐봇의 U/D≥1.5 하드 게이트 — 레포 밖, 사용자 전달 필요.
