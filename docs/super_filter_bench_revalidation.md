## §1. 사전등록

### 1.1 대상과 배경

- **재검증 대상**: `scripts/measurements/2026-09-03_super_filter_ev_90cp_revalidation.py`
  (결과: `docs/kr_us_strategy_map.md` "재검증 결과 — 우선순위6: 슈퍼대장 필터 EV").
- **이 스크립트에 기대고 있는 현재 판정**: **슈퍼대장 필터(눌림목 탭 `👑 슈퍼대장만`)
  채택 철회.** GUIDE.md "👑 슈퍼대장 활용법" 우선순위1이 철회로 갱신돼 있다. 코드 게이트가
  아니라 UI 토글이라 원복할 CONFIG는 없다.
- **재검증하는 이유**: 이 스크립트도 `harness.fetch_kr_benchmarks()` 기본값(900일=601봉)을
  썼다. 90개 체크포인트 중 off 410~600은 벤치마크 0.0 폴백, off 610~950은 자르지 않은
  전체 시계열(룩어헤드)이었다(v5.251에서 하네스는 실패하도록 고침). KR RS 순위(KS↔KQ)가
  틀어지면 눌림목 히트와 `analyze_super()` 소속 판정이 둘 다 바뀐다.

### 1.2 원래 판정 기준 — 그대로 재적용(완화도 강화도 금지)

원래 스크립트의 `window_report()`/판정 분기를 **import해서 그대로 호출한다**(재구현 없음).
원래 코드가 쓰는 조건은 **두 개뿐**이다:

1. `gap_R` = `슈퍼대장_소속` EV − `무필터_전체` EV > 0 (방향)
2. `harness.ev_gap_zscore(무필터_전체, 슈퍼대장_소속)`의 |z| ≥ 1.96 (유의)

둘 다 만족 → "방향 유지"(채택 철회 취소 후보), 아니면 → "격차 축소/역전 또는 유의성 상실"
(철회 유지). **원래 기준에 EV 절대 문턱도, 시기반분도, n≥100도 없다** — 5번(`_entry_close`)과
다른 점이라 여기서 그 조건들을 새로 얹지 않는다(강화도 판정 변경이므로). 스크립트의
`GAP_MIN_R = 0.05`는 코드 주석이 명시하듯 **참고용이고 사전등록 문턱이 아니다** — 판정에
쓰지 않는다.

**보조 지표(원래 스크립트가 이미 병기, 판정 아님)**: `소속 vs 비소속`(엄밀한 독립비교 —
소속은 무필터의 부분집합이라 1번 비교는 독립표본이 아님. 원래 측정도 같은 한계를 안고
있었고 그대로 유지한다), KR/US 분해(README 규칙8), 20개창 vs 90개창 병기.

### 1.3 원래 철회 근거 — 그리고 벤치마크 수정이 영향을 줄 방향 (사용자 요구 5)

**원래 결과(2026-09-03 실행)**:

| 창 | 무필터 EV(nv) | 소속 EV(nv) | 비소속 EV(nv) | gap | z | 판정 |
|---|---|---|---|---|---|---|
| 20개(off 60~250) | 0.0379 (1,636) | 0.0441 (227) | 0.0369 (1,409) | +0.0062 | 0.06 | 유의성 없음 |
| **90개(off 60~950)** | 0.0378 (10,272) | **−0.0199 (1,707)** | 0.0493 (8,565) | **−0.0577** | **−1.57** | **철회** |

소속 KR단독 −0.0892(nv 538) / US단독 +0.0120(nv 1,169).

**철회 근거는 두 조건 동시 실패다**: ① 방향이 역전(gap 음수) ② z −1.57로 유의성 없음.
즉 "EV 문턱 미달"이나 "시기반분 실패"가 아니라 **부호와 유의성 둘 다**였다.

**벤치마크 수정이 영향을 줄 수 있는 범위(실행 전 산술)**:
- 이 오염은 **KR RS 순위에만** 영향을 준다(US는 하네스가 벤치마크 차감을 생략 — 순위 불변).
  소속 표본 1,707건 중 KR은 538건(31.5%)뿐이고 나머지 1,169건(68.5%)은 **어떤 결과가
  나와도 그대로**다.
- US 소속분(+0.0120, n=1,169)을 고정한 채 KR 소속분만 바뀐다고 보면, 소속 EV가 무필터
  (0.0378)와 **동률이 되기만 해도** KR 소속 EV가 **−0.0892 → +0.0939 이상**으로
  0.18R 넘게 뒤집혀야 한다. 그 위에 z ≥ 1.96까지 필요하다.
- 따라서 **사전 예상은 "철회 유지"**다. 다만 벤치마크가 바뀌면 KR 히트 집합과 소속 판정
  자체가 재구성되므로(5번 재검증에서 돌파임박 KR 히트 수가 8,083 → 8,486으로 5% 바뀐
  전례) 소속 n과 무필터 EV도 같이 움직인다 — 위 산술은 "US를 고정한 단순 대입"일 뿐
  상한/하한이 아니다. **이 예상은 판정에 쓰지 않는다.** 결과가 예상과 다르면 예상이 틀린 것으로
  기록한다.

### 1.4 실행 설계 — 5번과 같은 4-run 구조

fetch 한 번을 네 실행이 공유한다. 한 번에 한 가지만 바꾼다.

| 실행 | 정의 | 차이가 보여주는 것 |
|---|---|---|
| **R0 원본 복제** | 원래 코드 그대로 + 오염된 벤치마크(900일 + 옛 폴백) 의도적 재현 | R0 − 원래(09-03 발표값) = 데이터 변동 |
| **R1 벤치마크만 수정** | R0에서 벤치마크 계산만 `harness.bench_score_at_date`(1900일) | R1 − R0 = **순수 오염 효과** |
| **R2 + 시총 필터** | R1 + KR 시총 1000억 추정 필터(RS 계산 전, KR만) | R2 − R1 = 순수 필터 효과 |
| R3 참고 | R2 + 프로덕션 데이터 경로(730일 창 + `clean_at_checkpoint` + 날짜 기준 truncate) | 판정에 쓰지 않음 |

**원래 실행과 날짜를 맞추는 방법**(5번과 동일):
- 원래 실행일은 **2026-09-03**. `Δ_kr` = KOSPI 캘린더에서 09-03 이후 봉 수, `Δ_us` = US
  거래일 수로 **시장별로 따로** 계산하고 assert한다(휴장일이 달라 값이 다를 수 있음).
  실제 offset = 원래 offset + Δ(해당 시장).
- fetch 시작일도 맞춘다: `kr_days = 1900 + Δd`, R0 벤치마크 `days = 900 + Δd`,
  US는 `us_period="5y"`(원래와 동일, 5년이면 Δd 7~9일 차이가 봉 수 하한에 영향 없음 —
  `assert_sufficient_depth`로 확인).
- **미래 구간은 2026-09-03까지만** 잘라 쓴다(원래가 본 정보 집합과 동일).
- 유니버스: KR은 `kr_universe_v6_1500_20260903_eod.json` + 정적 `KR_UNIVERSE` + 워치리스트.
  US는 현재 `get_universe("us")` — US 유니버스는 코드 파일이고 마지막 변경이
  `us_universe_ext.py` 2026-06-23 / `us_universe_auto.py` 07-03 /
  `us_universe_sectorleaders.py` 06-27로 **09-03 이후 변경 없음**(git 확인) → 당시와 동일.
- R0의 오염 재현은 v5.251에서 하네스가 실패하도록 고쳐졌으므로, 5번 스크립트
  (`2026-09-11_confirm_entry_close_bench_revalidation.py`)의
  `_legacy_bench_score_at_CONTAMINATED`를 **import해서 재사용**한다(사본을 또 만들지 않음).
  R1~R3가 그 함수를 호출하지 않았음을 assert로 확인한다.

### 1.5 판정 (재량 판단 금지)

- **R0 재현 게이트(사용자 지시, 선행 조건)**: R0의 nv가 원래 값(무필터 10,272 / 소속 1,707 /
  비소속 8,565)과 **±2% 이내**로 재현돼야 R1~R3 판정을 진행한다. 벗어나면 **멈추고 원인을
  보고**한다(판정 없음) — R0이 원래를 재현 못 하면 R1−R0을 "오염 효과"로 읽을 수 없기 때문.
- **판정 실행 = R1과 R2 둘 다.** 슈퍼대장 셀이 **두 실행 모두에서** 1.2의 두 조건
  (gap > 0 **그리고** |z| ≥ 1.96)을 만족 → **철회 취소, 슈퍼대장 필터 복원 후보**로 기록.
  **복원 자체는 별도 사전등록**(이 측정으로 UI·GUIDE를 바꾸지 않는다).
- **R1 또는 R2 중 하나라도** 두 조건 중 하나라도 미달 → **철회 유지.**
- R0·R3는 보고만 한다. 20개창 병기도 참고 기록이고 판정에 쓰지 않는다.
- 소속 KR단독이 음수여도(원래 스크립트의 분기처럼) 판정 문구에만 반영하고, 위 두 조건
  외의 새 기준으로 삼지 않는다.

### 1.6 보고 형식

1. **{원래(09-03 발표), R0, R1, R2, R3} × {무필터, 소속, 비소속, 소속 KR, 소속 US}** 표 —
   각 셀 EV와 nv, 그리고 gap/z. 판정이 바뀐 지점 표시.
2. **변화 분해**: gap과 z가 원래→R0(데이터 변동), R0→R1(**벤치마크 오염 효과**),
   R1→R2(시총 필터)에서 각각 얼마나 움직였는지. KR 소속 EV의 이동폭도 같이(1.3의 산술과 대조).
3. **해석 규칙(미리 정함)**:
   - R0 실패(원래와 같은 방향) & R1도 실패 → "원래 철회 판정은 벤치마크 오염과 무관하다."
   - R0 실패인데 R1 통과 → "**원래 철회는 벤치마크 오염 탓이었다**"(= 필터가 실제로는 유효했을
     가능성) → 복원 후보로 올리되 복원은 별도 사전등록.
   - R0부터 원래와 다르면 → "원래 결과가 데이터 변동에 민감"으로 기록하고, 판정은 R1/R2로.
4. 진단값: R0 복제 정확도(무필터/소속/비소속 nv를 원래 10,272 / 1,707 / 8,565와 비교),
   벤치마크 폴백 체크포인트 수(R0), 시총 필터 탈락 수(R2), 20개창 재현치.

### 1.7 룩어헤드 방지 — assert

- R1~R3: 벤치마크를 `cp_date`까지 자르고 마지막 날짜 == cp_date, 길이 ≥ 253 확인
  (`harness.bench_score_at_date`가 이미 실패시킴).
- 전 실행: 미래 구간의 첫 날짜 > 해당 체크포인트 날짜, 마지막 날짜 ≤ 2026-09-03.
- Δ 계산 후 `cal[-(60+Δ_kr+1)]`이 원래 off 60의 날짜(2026-09-03 기준 60봉 전)와 같은지 assert.
- R1~R3가 오염 재현 함수를 호출하지 않았음을 호출 카운터로 assert.
- R3 한정: analyze에 들어가는 df의 마지막 날짜 == cp_date.

### 1.8 알려진 한계 (실행 전 선언)

- **유니버스 드리프트**: KR은 2026-09-03 유니버스를 4년 전 체크포인트까지 그대로 쓴다.
  과거 각 시점의 거래대금 상위 유니버스는 재구성 불가(EOD 파일이 09-01부터만 존재).
  원래 측정도 같은 한계라 비교는 공정하지만, 둘 다 "그날 프로덕션이 본 목록"은 아니다.
- **소속 vs 무필터 z의 비독립성**: 소속은 무필터의 부분집합이라 `ev_gap_zscore`의 독립표본
  가정이 엄밀히는 깨진다. 원래 기준을 그대로 쓰기 때문에 이 한계도 그대로 남고, 보조로
  `소속 vs 비소속`(독립)을 병기한다.
- **시총 필터는 KR만** 적용된다(프로덕션이 KR에만 적용). US 소속분에는 R2에서도 변화 없음.
- 이 측정은 "필터를 켜면 더 좋은가"만 본다. 필터를 켰을 때 줄어드는 기회 수(소속 n이 전체의
  약 17%)는 원래 측정도 판정에 넣지 않았다.

## §1-부록. 실행 중 변경 기록

- **버그 수정(결과를 보기 전, 첫 실행이 크래시해서 — 2026-09-12):** R3(참고 실행)에서
  종목을 **날짜 기준**으로 자르면서 미래 구간은 **offset 기준**으로 잡아, 봉이 빠진 종목
  (예: `042670.KS`)에서 미래 구간 시작일이 체크포인트보다 앞서는 경우가 생겼다. 룩어헤드
  assert(1.7)가 이걸 잡아 첫 실행이 중단됐다 — **R3만의 버그**이고 R0~R2는 offset 기준으로
  일관돼 영향 없음(재실행 후 R0~R2 값이 첫 실행과 완전히 동일한 것으로 확인). R3의 미래
  구간도 날짜 기준(`index > cp_eff[ticker]`)으로 바꿔 재실행했다. 판정 실행(R1·R2)의 정의는
  바뀌지 않았다.

## §2. 결과 (2026-09-12 실행)

근거 스크립트: `scripts/measurements/2026-09-12_super_filter_bench_revalidation.py`
(fetch 453초 + R0~R3 병렬 534초). 유니버스 KR 1,503 + US 2,354, fetch 성공 3,614종목.
Δ_kr=6봉 / Δ_us=5봉(시장별 따로 계산, assert 통과).
