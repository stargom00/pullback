## §1. 사전등록

### 1.1 대상 · 원래 결론 · 화면 영향

- **재검증 대상**: `scripts/measurements/2026-09-02_post_entry_stall_exit_ev.py`
  (결과 문서: `docs/post_entry_stall_exit_ev.md`, 결과 JSON도 예외적으로 커밋돼 있음).
- **원래 결론**: **기각.** "정체(스톨)를 만나면 조기청산하라"는 규칙은 채택 기준을 통과한
  조합이 **27개 중 0개**라 도입하지 않았다. 방향성(계속보유 B > 즉시청산 A)은 27개 중
  26개에서 관측됐고 다수가 z≥1.96으로 유의했지만 **격차가 +0.02~+0.10R대로 문턱(+0.15R)에
  못 미쳤다.** 가장 근접한 박스돌파 N5/X3%도 gap +0.140 / z 1.93 / n 368.
- **화면 영향 없음(중요)**: 이 측정의 결론은 "**규칙을 만들지 않는다**"였다. scanner.py·
  app.py·static/index.html 전부 무수정이고 배지·문구·게이트가 하나도 없다. 따라서
  **기각이 유지되든 뒤집히든 이번 재검증으로 바뀌는 화면은 없다.** 뒤집히는 경우에도
  "규칙 신설 후보"로 기록만 하고, 실제 도입은 **별도 사전등록**이다(사용자 지시).
- **재검증 이유**: 이 스크립트도 `harness.fetch_kr_benchmarks()` 기본값(900일)을 써서
  off 410 이상 체크포인트의 KR RS가 오염됐다. 원래 결론이 "KR은 보유 우위가 약하거나
  역전"이라는 KR/US 분해에 기대고 있어, KR 쪽 코호트가 바뀌면 서술이 달라질 수 있다.

### 1.2 원래 판정 기준 — 그대로 재적용

원본의 `analyze_combo` / `paired_zscore` / `summarize_rows` / `time_split_check`를
**import해서 그대로 호출한다**(재구현 없음). 조합별 채택 조건은 셋 다 만족:

1. `gap(B−A) ≥ +0.15R`(`GAP_MIN_R`)
2. 대응표본 z ≥ 1.96 — A/B가 같은 히트에서 갈라진 짝지은 표본이라 원본이 자체
   `paired_zscore`(diff 평균/표준오차)를 쓴다. 이번에도 그대로 쓴다.
3. 시기 반분(전반/후반) 둘 다 gap ≥ +0.15R

격자도 그대로: N ∈ {2,3,5} × X ∈ {2%,3%,5%} × 3탭(눌림목/돌파임박/박스돌파) = **27조합**.
정체 정의(진입 후 N일 동안 손절·2R 미도달 AND 매일 종가가 진입가 ±X% 밴드)도 그대로.

### 1.3 R0 앵커 판단 — (a) 09-02 확정봉 기준으로 간다

**원본 실행 시각: 파일 mtime 09-02 18:33 NZST = KST 15:33.** KR 정규장 마감 15:30 직후,
종가 확정 공표(15:30~15:40) 구간이다. US는 그 시각 09-02 02:33 ET로 **당일 미개장**이라
마지막 US 봉은 09-01이다.

| 안 | 내용 | 판단 |
|---|---|---|
| **(a) KR 09-02 확정봉 기준(Δ_kr = 09-02 이후 KR 봉 수 = 7)** | 원본이 받은 09-02 봉이 이미 확정 종가였다고 보는 안 | **채택(주 앵커)** |
| (b) KR 09-01 기준(Δ_kr = 8) | 09-02 봉이 아예 없었다고 보는 안 | 8·9번(개장 전 실행)과 달리 여기선 근거가 약함 — 15:33엔 09-02 봉이 존재한다 |
| (c) 재현 불가 종결 | 미완성 봉 상태는 복원 불가라는 안 | 검증 전에 단정하지 않는다 |

**(a)를 고른 근거**: 8·9번은 *개장 전*이라 그날 봉이 **아예 없었고**(그래서 하루 앞으로
당기자 ±1.3%로 재현됐다), 이번은 *마감 직후*라 그날 봉이 **존재하고 종가도 사실상
확정**이다. 남는 불확실성은 "15:33 시점 naver 종가가 최종 종가와 미세하게 달랐을 수
있다" 정도인데, 이건 **가장 최근 체크포인트(off=60) 한두 곳의 미래 구간 마지막 봉**에만
영향을 주고 정체 판정(N ≤ 5일)·레이스(60봉)의 대부분 구간은 과거에 고정돼 있다.

**결정 트리(결과 보기 전 확정)**:
1. (a)로 R0 실행 → **R0 재현 게이트 통과 시 그대로 판정 진행**.
2. 게이트 실패 시 → **(b) Δ_kr+1 진단 실행**(8·9번과 같은 방식, R0만). (b)가 게이트를
   통과하면 앵커를 (b)로 바꿔 R1~R3 재실행하고, 그 경위를 §1-부록에 "블라인드 상태"와
   함께 기록한다.
3. (a)·(b) 둘 다 실패 → **(c) 재현 불가로 종결**(판정 없음). 원본 결론은 "장중 실행으로
   입력 재현 불가, 재검증 미완"으로 표시하고, 화면 영향이 없으므로 그 외 조치는 없다.

**US 앵커(주의)**: 앞선 재검증들과 달리 **US는 09-01이 마지막 봉**이다(실행 시각이 ET
기준 09-02 새벽). 그래서 US 미래 구간은 **≤ 2026-09-01**로 자르고 Δ_us는 09-01 이후 US
거래일 수로 계산한다 — ORIG_DATE(09-02)를 그대로 US에도 쓰면 아직 열리지 않은 09-02
봉이 섞인다. 실행 시 assert로 확인한다.

### 1.6 판정 (재량 판단 금지)

- **판정 실행 = R1과 R2 둘 다.** 어떤 조합이 **두 실행 모두에서** 1.2의 세 조건을 전부
  통과하면 그 조합은 "채택 후보"로 **기록만** 한다 → 실제 규칙 도입은 **별도 사전등록**.
- 하나라도 미달이면 그 조합은 **기각 유지**. 27조합 전부 미달이면 **원래 결론(기각) 유지**.
- **화면·코드 변경은 어느 경우에도 이번 범위 밖**이다(1.1 참고).
- KR/US 분해(원래 문서의 "KR은 보유 우위 약함/역전" 서술)는 **판정이 아니라 서술**이므로,
  R1/R2에서 그 방향이 바뀌면 §2에 "원래 서술 수정 필요"로 기록한다(문서 수정은 별도).

### 1.7 사전 예상 (기록만, 판정에 안 씀)

**27조합 전부 기각 유지 예상.** 근거: 가장 근접한 조합이 gap +0.140(문턱 −0.010)·z 1.93
(문턱 −0.03)이고, 앞선 재검증에서 측정된 벤치마크 수정 효과는 2번 gap +0.007R, 7번 z +0.36,
8번 z +0.35~0.65 수준이다. 박스돌파 N5/X3%(n=368, KR 비중이 크면 더 움직일 수 있음)가
유일하게 문턱을 넘을 여지가 있는 조합이다. 빗나가면 예상이 틀린 것으로 §2에 적는다.

## §2. 결과 — **판정 없음 (재현 불가 종결)**

**실행**: 2026-09-12 KST 20:47 (NZST 23:47). KR 앵커 2026-09-02 / US 앵커 2026-09-01,
Δ_kr = Δ_us = 7. `short_future` 0건, 룩어헤드 assert 통과.

### 2.1 R0 재현 게이트 — (a)·(b) 둘 다 실패

| 조합 | 원본 n_stall | (a) 09-02 확정봉 | (b) Δ_kr+1 (09-01) |
|---|---|---|---|
| 눌림목 N2/X2% | 3,552 | 3,446 (**−2.98%**) ❌ | 3,455 (**−2.73%**) ❌ |
| 돌파임박 N2/X3% | 10,559 | 10,405 (−1.46%) ✅ | 10,454 (−0.99%) ✅ |
| 박스돌파 N5/X3% | 368 | 366 (−0.54%) ✅ | 338 (**−8.15%**) ❌ |

→ 둘 다 게이트 실패. **§1.3 결정 트리 3단계 = (c) 재현 불가로 종결.**

**(b)가 (a)보다 나쁘다**는 점이 핵심이다. 8·9번(개장 전 실행)에서는 하루 당기는 것이
정확한 교정이어서 전 조합이 게이트 안으로 들어왔는데, 여기서는 눌림목이 −2.98%→−2.73%로
거의 안 움직이는 동안 박스돌파가 −0.54%→−8.15%로 크게 나빠졌다. 즉 **앵커를 하루 당기는
방향은 교정이 아니며, 원본이 본 15:33 시점의 입력 상태는 09-02 확정봉으로도 09-01
확정봉으로도 복원되지 않는다.** (마감 직후라 09-02 봉 자체는 존재했으므로 (a)가 구조적으로
맞는 앵커인데도 눌림목이 −3%를 넘겼다 — 남는 차이는 앵커가 아니라 유니버스·데이터 드리프트
쪽으로 보이나, 이번 범위에서 원인을 특정하지 않는다.)

### 2.2 참고 — (a) R0의 게이트 대상 3조합 수치 (판정에 쓰지 않음)

게이트를 통과하지 못한 실행이므로 **아래 값으로 채택·기각 판정을 하지 않는다.** 재현
실패의 크기를 보이기 위해서만 남긴다.

| 조합 | 원본 (A / B / gap / z) | R0(a) (A / B / gap / z / n) |
|---|---|---|
| 눌림목 N2/X2% | 0.047 / 0.148 / +0.101 / 4.28 | 0.058 / 0.151 / +0.094 / 3.88 / 3,446 |
| 돌파임박 N2/X3% | 0.058 / 0.122 / +0.064 / 4.75 | 0.053 / 0.140 / +0.086 / 6.31 / 10,405 |
| 박스돌파 N5/X3% | −0.009 / 0.130 / +0.140 / 1.93 | 0.004 / 0.232 / +0.228 / 3.04 / 366 |

R0(a)에서는 박스돌파 4조합이 채택 3조건을 통과했다. 그러나 이는 **원본을 복제하지 못한
실행의 결과**이므로 "뒤집혔다"고 말할 수 없다 — R1·R2(정식 판정 실행)는 게이트 실패로
아예 돌리지 않았다.

### 2.3 조치

- **원본 결론(정체 조기청산 기각)은 그대로 둔다.** 단 `docs/post_entry_stall_exit_ev.md`와
  대기 목록에 **"장중(KST 15:33) 실행으로 입력 재현 불가 — 벤치마크 재검증 미완"**으로
  표시한다.
- **화면·코드 변경 없음**(§1.1: 이 측정은 애초에 규칙을 만들지 않았다). 재검증이 미완이어도
  프로덕션에 미치는 영향은 0이다.
- 2.2가 시사하는 "박스돌파 정체 구간은 보유 우위가 문턱을 넘을 수 있다"는 가능성은
  **근거로 쓸 수 없다.** 다시 보려면 **재현 가능한 앵커(장 마감 후 확정 시각)에서 원본
  측정 자체를 새로 설계·사전등록**해야 한다. 이번 결과를 인용해 규칙을 만들지 않는다.

### 2.4 사전 예상 대비

§1.7의 예상은 "27조합 전부 기각 유지"였다. 판정 자체가 성립하지 않았으므로 **예상은
맞지도 틀리지도 않았다**(적중 여부 판정 불가). 다만 §1.8이 경고한 "장중 실행이라 R0 복제
