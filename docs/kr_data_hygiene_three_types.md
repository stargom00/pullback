# 데이터 위생 3종 — 가격고정 / 코퍼레이트 액션 / 거래정지 (2026-09-01)

036800(나이스정보통신) 조사(`docs/kr_universe_coverage_investigation.md`)
중 거래정지 구간이 지표 계산을 왜곡할 수 있다는 문제가 나와, 기존에
이미 다루고 있던 "가격고정" 필터와 함께 3종을 한 곳에 정리한다. 셋 다
"정상적인 가격 움직임이 아닌 구간이 스캐너 지표에 섞여 들어온다"는 같은
범주의 문제이지만 원인과 대응 상태가 다르다.

## 1. 가격고정 (M&A/특수상황 의심) — 감지 O, 대응 완료 (v5.90)

`scanner.price_frozen_check()`. 인수합병 발표 후 인수가 부근에 가격이
고정되는 패턴(변동성 붕괴)을 탐지. 조건: ① 과거 5~120봉 구간에 거래량
5배+ 동반 +15%↑ 급등(발표충격갭) **AND** ② 최근 20봉 ATR% < 0.5%(변동성
극소). CRNX/APGE 실제 M&A 사례로 캘리브레이션 완료, 정상 신고가 주도주와
22배+ 마진으로 분리 확인됨. 전 탭 공통 유틸(`_price_frozen_block`)로
정보용 필드 제공(하드 게이트 아님, 각 탭이 필요한 대로 사용).
상세: `docs/price_frozen_calibration.md`.

**한계**: 조건1(선행 발표충격갭)이 없는 가격고정 — 예: 일반 관리종목
정리매매 전 단계처럼 뚜렷한 사전 급등 없이 서서히 변동성이 죽는 경우 —
는 안 잡힌다. 지금까지 실제로 문제된 사례가 M&A 케이스뿐이라 미해결로
남겨둠(필요성 확인 전까지 확장 안 함).

## 2. 코퍼레이트 액션 (액면분할/병합 등) — 감지 로직 없음, 필요성도 낮음

036800 조사에서 직접 확인: `naver_kr.fetch_history()`가 반환하는
과거 시계열은 **분할 전후 구간이 완전히 연속적**이다(2022-07~2026-08
4년치, 어떤 이산 점프도 없음). naver_kr.py 자체에는 분할조정을 위한
코드가 전혀 없지만, 업스트림(네이버 금융)이 이미 수정주가를 반환하는
것으로 보인다 — 우리 쪽에서 별도 감지·보정 로직을 추가할 필요가 확인된
적이 없다.

**주의**: 이건 "네이버가 조정을 잘 해준다"는 관찰이지 우리가 검증한
보장이 아니다. 향후 실제 액면분할 종목에서 이상 징후(RS/MA 급변)가
보이면 제일 먼저 `/api/debug/{ticker}`로 원본 시계열의 연속성부터
확인할 것 — 지금은 발생한 적 없어 대응 코드를 만들지 않았다.

## 3. 거래정지(0거래량) — 부분 대응 완료(v5.129), 잔여 갭 있음

### 3-1. 거래량평균 희석 (vol_mult 부풀림) — 수정 완료 (v5.129)

**문제**: `vol_mult = 오늘거래량 / 트레일링N봉평균거래량`을 계산하는
모든 곳이 `.mean()`을 단순 적용했다. 거래정지(거래량 0)로 인한 0값이
분모 창에 섞이면 평균이 희석돼, 정지 재개일의 `vol_mult`가 실제보다
부풀려진다 — 재개 첫날 평범한 거래량도 "폭발적 거래량 동반 돌파"처럼
보일 수 있음.

**실측(2026-08-31, KR 1,504종목 전체)**: 트레일링 50봉 창에 0거래량이
1개 이상 섞인 종목 51개(3.4%) — 이 중 23개는 창 전체가 0(완전정지 지속
중, `vol_avg=0`이라 기존에도 게이트 자동 실패로 안전했음), **28개는
부분정지(실제 왜곡 위험군)**로 `vol_mult`가 최대 9.71배까지 부풀려져
있었다. 부분정지 28개 중 13~14개가 이미 여러 탭의 게이트 기준(1.5배)을
넘는 값을 보임.

**수정**: `scanner.nonzero_vol_mean(window)` 신설(0거래량 봉을 제외한
평균, 창 전체가 0이면 기존처럼 0.0 반환해 완전정지 종목은 계속 게이트
실패). 다음 7곳 전부 교체:
- `volume_info()`(카드 표시 avg_volume/vol_vs_avg)
- `analyze_breakout()`, `analyze_boxbreak()` — 50봉 평균
- 패턴/급등 탭(`_pat_*` 계열) — 20봉 평균 + quiet_vol_max 비교 2곳
- quiet_accum 실격판정("이벤트성" 체크)
- `analyze_imminent()`(돌파임박) — 20봉 평균
- `theme_reignition.check_confirm()`(재점화 확인진입, 실거래 알림 경로)

**수정 전/후 실측 비교(오늘자 KR 유니버스, 1.5배 게이트 기준)**:

| 종목 | 수정 전 vol_mult | 수정 후 vol_mult | 결과 |
|---|---|---|---|
| 알에프세미(096610.KQ) | 5.19 | **0.42** | 가짜 통과 제거 |
| 한국캐피탈(023760.KQ) | 2.19 | **1.36** | 가짜 통과 제거 |
| 트리니티항공(091810.KS) | 1.85 | **1.29** | 가짜 통과 제거 |
| 엑사이엔씨 외 12종목 | 1.66~9.71 | 1.51~6.8 | 여전히 게이트 통과 유지(진짜 고거래량) |

3건이 순수 분모 희석으로 인한 가짜 게이트 통과였고, 12건은 수치가
낮아지긴 해도 여전히 임계값을 넘는 실제 고거래량임을 확인 — 과잉 수정
아님.

**보류한 사이트**: `analyze_turnaround`(추세전환)의 `vol_ratio`/
`breakout_vol`은 하드 게이트가 아니라 점수·배지 보너스로만 쓰여
영향이 작아 이번엔 손대지 않음(가짜 히트가 아니라 가짜 배지/점수
문제라 우선순위 낮음). `analyze_breakdown`(역ETF 숏 이탈)의
`vol_expand`, `_pat_surge_accum`(ABC 문서방식, 이미 조사 후 보류된
탭 — `docs/abc_doc_style_tab_investigation.md`)도 같은 이유로 보류.
필요해지면 같은 `nonzero_vol_mean()`으로 교체하면 됨(패턴은 이미
확립돼 있음).

### 3-2. O/H/L=0 구간 (장기 거래정지) — 미수정, 실사용 영향은 현재 제한적

036800(3주 단기정지) 조사 중에는 정지 구간이 `O=H=L=C=직전종가`로
평평하게 forward-fill돼 있어 문제가 없었는데, **알에프세미(096610)의
-95.2% "급락"을 직접 조사하며 다른 패턴을 발견**했다: 2026-06-04~08-24
(약 3개월) 장기 거래정지 구간에서 naver_kr이 반환하는 값은
`Open=High=Low=0.0, Close=직전 체결가 그대로 유지(2965원), Volume=0`
— **O/H/L만 0으로 꺼지고 Close만 유지되는 비대칭 패턴**. 동일 패턴을
금양(001570)·카프로(006380)·아스타(246720) 등 "완전정지 지속 중" 종목
전부에서 재확인(4종목 표본 전부 재현) — naver_kr.py 자체 코드에는 이런
로직이 없어, **네이버 원본 데이터가 장기정지 종목에 대해 이렇게 표시하는
것**으로 보인다(단기정지 036800과는 다른 표시 방식 — 정지 사유/기간에
따라 네이버 쪽 처리가 다른 듯).

**왜 지금 당장 히트를 오염시키지 않는가**: 이 패턴이 나타나는 종목은
전부 "현재도 거래정지 중"(Volume=0이 오늘까지 이어짐)이라, 오늘자
히트를 만드는 어떤 탭의 게이트도(오늘 종가 갱신·거래량 조건 등) 애초에
통과할 수 없다. 재개되는 날엔(096610처럼) 거래량이 실리므로 3-1의
`vol_mult` 문제는 이번 수정으로 커버되지만, **재개일 기준 트레일링
Low.min() 기반 손절가·피벗 계산에 0이 섞여 들어가면 손절가가 0 근처로
계산 → risk_pct가 비정상적으로 커짐 → 기존 손절폭 하드게이트
(`_risk_hard_ok`)가 이런 종목을 어차피 걸러낼 가능성이 높다**(직접
검증은 안 함 — 별도 측정 필요). 즉 별개의 두 안전장치(거래량 게이트,
리스크% 게이트)에 우연히 이중으로 걸리는 구조라 지금까지 실제 오염
사례가 보고된 적은 없다.

**직접 확인됨(v5.129 스모크 테스트)**: 096610(알에프세미)에
`theme_reignition.check_confirm()`을 실행하면 `stop: 0.0`이 그대로
나온다(Low.min()이 halt 구간의 0을 그대로 반영) — 예측이 아니라 실측
확인. 다행히 `analyze_breakout`/`analyze_boxbreak`는 이 종목에 대해
None(가드에서 이미 탈락)을 반환해 무해했지만, `stop=0.0`이 downstream
risk_pct 계산까지 갔다면 극단값(거의 100%)이 되어 손절폭 게이트가
잡아줄 가능성이 높다는 가설과 일치한다.

**남은 진짜 갭**: 재개 후 최대 250거래일 동안(0값이 rolling window에서
밀려날 때까지) `off_high_pct`·RS의 "12개월 고점" 계산에 이 정지 기간의
**직전 동결가**(096610: 2965원, 실제 재개가 141원 대비 약 21배)가
"52주 신고가"로 잡혀있을 수 있다 — 이건 하드게이트가 아니라 점수/배지에
영향을 주므로 리스크%처럼 자동으로 안 걸러진다. **근본 수정안**(적용
안 함, 사용자 결정 대기): `naver_kr.fetch_history()`에서 0거래량 행을
아예 드롭하거나 O=H=L=C로 일관되게 forward-fill — 이렇게 하면 3-1의
`nonzero_vol_mean()` 수정도 사실상 불필요해지고(원천에서 이미 정리),
Low.min()/High.max() 계열 전체가 한 번에 안전해진다. 다만 이건
`naver_kr.fetch_history()`를 쓰는 모든 코드(백테스트 스크립트 포함)의
날짜-포지션 대응을 바꾸는 더 큰 변경이라 이번 라운드에서는 보류.

## 재검토 트리거

- 3-1의 `analyze_turnaround`/`analyze_breakdown`/`_pat_surge_accum`
  잔여 사이트에서 실제로 배지/점수 왜곡 사례가 관측되면 그때 같은
  헬퍼로 교체.
- 3-2의 O/H/L=0 종목이 재개 후 실제로 RS/off_high_pct 왜곡된 채 상위
  랭크에 뜨는 사례가 발견되면, `naver_kr.fetch_history()` 소스단
  수정(0거래량 행 드롭 또는 forward-fill)을 실행.
- 2절(코퍼레이트 액션)은 실제 이상 사례가 나오기 전까지 대응 코드
  없이 관찰만 한다.
