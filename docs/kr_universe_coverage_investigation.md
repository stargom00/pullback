# KR 유니버스 커버리지 조사 (2026-08-31)

계기: 나이스정보통신(036800.KS)이 TradingView에서 2026-07-22 무렵
29,000원→7,500원으로 급락한 것처럼 보인다는 제보 — 액면분할 조정 누락
의심으로 시작, 조사 중 "이 종목이 우리 KR 유니버스에 아예 없다"는 더
근본적인 문제로 범위가 넓어짐. 우리기술(056360.KQ)도 과거 유사 사례로
언급됨.

## 1. 036800 분할/급락 여부 — 원래 질문의 답

`naver_kr.fetch_history('036800', days=1500)`로 **2022-07-25~2026-08-31,
4년 연속 데이터**를 확인:

- 이 기간 전체 최고가 7,550원(2026-08-25), 최저가 3,348원(2025-02-03).
  **29,000원 근처에 간 적이 단 한 번도 없고, 2026-07-22 전후 어떤 이산
  점프도 없음.**
- 2026-07-29~08-17 사이 거래량 0(거래정지로 추정) 구간 존재. 재개 후
  08-18(6,150원)→08-31(7,500원)로 자연스럽게 상승 — 유저가 본 "7,500"은
  이 기간의 **오늘(8/31) 종가**와 일치하는 것으로 보임.
- `finance.naver.com/item/main.naver?code=036800` 페이지 타이틀 확인 →
  "나이스정보통신"(유저가 말한 회사명과 일치, NICE평가정보 030190과는
  별개 회사 — 티커 자체는 맞음).

**결론: 분할조정 버그 정황 없음.** TradingView의 "29,000→7,500"은 우리
데이터로 재현되지 않는다 — 종목/차트 혼동이거나 훨씬 이전 시점 가격을
착각했을 가능성이 높다. naver_kr의 분할조정 로직 자체는 이 케이스로는
문제를 찾지 못했다(4년 연속 데이터에 이산점이 전혀 없다는 게 반대증거).

참고로 전체 유니버스(1,504종목) 대상 최근 250일 단일거래일 ±40%/2배
급변 스캔에서는 036800과 무관한 별개 종목 2건만 나옴(알에프세미
096610.KQ -95.2%/2026-08-25, 폰드그룹 472850.KQ -47.3%/2026-01-02) —
이쪽은 별도 조사 대상.

## 2. KR 유니버스 구성 방식

`universe.py`의 `get_universe('kr')` = 정적 `KR_UNIVERSE`(254종목,
하드코딩) ∪ 동적 `naver_kr.fetch_top_value(KR_TOP_N=1500)`(당일 거래대금
상위) 병합 → 실측 총 1,504종목.

036800·056360 둘 다 정적 리스트에 없고, 조사 시점 거래대금 상위 1500(및
`top_n=3000`으로 확대 요청해도)에도 없음 — 완전히 제외.

## 3. 누락 규모 측정

`fetch_top_value(top_n=3000)`으로 확대 요청해도 실제 반환은 **KOSPI 572
+ KOSDAQ 1005 = 1,577개**뿐(036800·056360 이 3000개-요청 결과에도 없음).
`naver_kr.py:322-388`의 페이지네이션 로직(`sise_quant` 페이지, 빈 페이지
2연속이면 중단) 때문 — **파싱 버그가 아니라 네이버 거래대금 순위 페이지
자체가 그 지점에서 끝남**(그날 거래대금 랭킹에 오르는 종목이 코스피
572·코스닥 1005개뿐이라는 뜻). KOSPI/KOSDAQ 전체 상장사(약 2,600여개)
대비 훨씬 적다.

- **KR_TOP_N=1500 설정은 이미 "거래대금으로 랭킹 매겨지는 풀"(1,577개)을
  거의 다 커버**하고 있음.
- 나머지 약 1,100여개는 애초에 네이버 거래대금 랭킹 페이지에도 안 뜨는
  초저유동성 종목군.
- 036800(나이스정보통신)은 최근 중앙값 거래대금 약 9.7억원/일,
  056360(우리기술)은 약 2.8억원/일 — 완전 무유동은 아니지만 거래량이
  일별 10배 이상 널뛰어(036800: 2.7만~60만주) 1,577개 랭킹 풀의 경계선
  안팎을 오갈 가능성이 높다.

전체 KRX 상장(약 2,600여개) 대비 우리 유니버스(1,504) 커버리지는 약
58%.

## 4. 판정 — 의도된 필터인가 버그인가

**의도된 유동성 필터의 정상 결과, 버그 아님.** `fetch_top_value` 자체는
정상 동작(빈 페이지 감지 → `fetch_top_marketcap()` 병합 폴백까지 정상
수행). 파싱 실패였다면 애초에 리스트가 비거나 예외가 났을 것 —
036800/056360이 빠진 것은 "거래대금 랭킹 페이지 자체에 그 정도 순위가
없다"는 정상 동작의 결과다.
