# 눌림목 탭 개선 — 손절폭 배지 UI + 확인 후 진입 측정 (2026-08-14)

사용자 요청 3가지(①②는 UI, ③은 측정) 처리 기록. ③ 측정 결과가 ①의 전제
자체를 뒤집어서, UI 반영 방향도 원래 요청과 달라졌다 — 그 경위를 그대로 남긴다.

## 방법론

`docs/all_tabs_common_yardstick_investigation.md`의 시점매칭 체크포인트 방식을
그대로 재사용: `off=60..250`(10 간격, 20지점) 전체 유니버스(KR 1503 + US 2120,
delisted 4종목 제외 실제 3612종목 페치)에 대해 각 체크포인트마다 데이터를 그
시점까지 잘라(`df.iloc[:len(df)-off]`) `analyze()`류 함수를 실제로 돌리고,
그 뒤에 남은 `off`봉의 미래 데이터로 2R 레이스를 진행. RS/RS모멘텀도 체크포인트
시점 기준으로 재계산(미국은 단일 벤치마크라 랭킹에 상수 오프셋이라 벤치마크
차감 생략 — 순위 불변; 한국은 코스피/코스닥 벤치마크를 같은 오프셋으로 truncate
해서 반영). 레이스: 진입 후 최대 60봉, 저가≤손절 우선 판정, 목표(진입+2×리스크)
도달, 60봉 내 미해결="미결"(0R, 분모 포함), 가용 데이터가 60봉 미만인 채
미해결="데이터부족"(분모 제외) — 이번 측정에선 전부 off≥60이라 데이터부족 0건.

전 코드는 `/private/tmp/.../scratchpad/measure.py`(1회성, 저장소에 커밋 안 함,
prior 조사들과 동일 관례). **v5.67에서 저유동성 하드 필터 재현을 추가**(아래
"기준선 불일치 조사" 참고) — 이 문서의 모든 수치는 그 반영 이후 최종본이다.

## 기준선 불일치 조사 (v5.67) — 원인 특정은 실패, 재현성으로 대체

최초 측정(위 방법론 그대로, 저유동성 필터 없이) 결과 눌림목 전체 EV가 0.286R
(n=1648)로 나왔는데, 이는 `all_tabs_common_yardstick_investigation.md`의 기존
Script A 기록치 0.172R(n=1787, 일평균 89.4)과 66% 차이가 났다. 사용자가
"필터 방향 결론보다 이게 더 급하다"고 짚어서, ①③ 결론에 쓰기 전에 원인을
특정하는 조사를 먼저 진행했다.

### 확인한 것 (전부 일치 — 버그 아님)

1. **체크포인트/레이스 스펙**: `off=60..250` 20지점, 진입=신호일 종가,
   손절=`analyze()`가 반환하는 stop 필드(모드 재정의 없음), 목표=진입+2×리스크,
   60봉 레이스, 저가≤손절 우선판정, 미결=0R(분모 포함), 데이터부족만 분모
   제외 — 전부 `all_tabs_common_yardstick_investigation.md` 방법론 절 원문과
   대조해 문구 그대로 일치 확인.
2. **RS 계산 정합성**: 내 체크포인트 코드의 RS 산출 로직을 app.py
   `_fetch_market_data_inner`의 실제 코드(2921~2939행)와 나란히 재현해
   비교 — 3512종목 전원 랭크 완전 일치(diff 0건).
3. **미국 벤치마크 생략 가정 검증**: "미국은 단일 벤치마크라 상수 이동,
   순위 불변"이라는 가정을 실제 나스닥종합(^IXIC) 지수로 직접 검증 —
   벤치마크 차감 있음/없음 랭크가 2036종목 전원 완전 일치(mismatch 0건).
4. **레이스 로직 수동 트레이스**: 4종목(005930.KS 등)을 entry/stop/target과
   실제 미래 10봉의 저가·고가를 나란히 출력해 손절/목표 판정이 계산대로
   맞는지 눈으로 확인 — 정상.
5. **CONFIG 드리프트**: `all_tabs_common_yardstick_investigation.md` 작성일
   (2026-08-08) 이후 scanner.py 변경 이력(v5.57~v5.65)을 전부 diff로 확인.
   눌림목에 영향 있는 변경은 v5.60의 `ma20_slope_floor`(주도주만 0.98 →
   전종목 0.98) 하나뿐이고, 이건 **완화**라 히트 수가 늘어나는 방향이어야
   하는데 실제론 내 쪽 히트가 더 적다(1648 vs 1787) — 방향이 반대라 이
   변경으로는 설명 안 됨. v5.61~v5.65는 scanner.py `analyze()`(눌림목)를
   건드리지 않음(app.py의 진단 함수/테스트 인프라만 변경).

### 찾아서 고친 것 (실재하지만 격차의 원인은 아니었음)

**저유동성 하드 필터 누락**: `app.py`의 `run_scan()`은 `analyze()`가 히트를
반환한 뒤 평균거래대금(KR 3억원/일, US $2M/일) 미만을 추가로 걸러낸다
(v4.52, `scanner.py` 안이 아니라 `app.py` 쪽에 있음). 이 조사에서 쓴
`measure.py`는 `analyze()`를 직접 호출해서 이 필터를 안 거쳤다 — 실서비스
화면엔 안 보이는 저유동성 종목이 측정엔 섞여 있었다는 뜻. 필터를 추가해
재측정했지만 **영향은 미미**했다(눌림목 n 1648→1623, EV 0.286→0.291) — 격차의
원인은 아니었지만, 그 자체로 실서비스와 안 맞는 진짜 gap이었으므로 계속
반영한다. 이 문서의 모든 최종 수치는 이 필터 포함 버전이다.

### 결론 — 특정 실패, 그러나 재현 가능한 쪽을 채택

Script A의 원본 코드가 저장소에 남아있지 않아(이 프로젝트의 표준 관례상
1회성 측정 스크립트는 커밋하지 않는다 — 이번 측정도 마찬가지로 안 남는다)
정확히 뭐가 달랐는지 **특정하지 못했다**. 다만 이번 측정은:
- 방법론 문서 원문과 항목별로 대조 확인됨
- RS/벤치마크 로직이 프로덕션 코드와 독립적으로 완전히 일치함이 검증됨
- 레이스 로직이 수동 트레이스로 확인됨
- `analyze()`를 직접 호출(트레이스 사본 아님 — v5.61~v5.65에서 반복
  발견됐던 "진단 함수가 실제 로직과 드리프트"하는 유형의 버그가 원천
  차단됨)
- 프로덕션의 저유동성 필터까지 재현함

**이 재현 가능성 자체를 근거로 이번 측정치를 채택**하고, 기존 Script A
수치(눌림목 0.172, 추세전환 0.362, 돌파 0.311, 박스돌파 0.336, 돌파임박
0.241)는 재현 불가로 신뢰도가 낮다고 판단해 `all_tabs_common_yardstick_investigation.md`
상단에 "이후 재측정으로 대체됨" 노트를 추가했다. 아래 ①③의 모든 수치는
이번 재측정(저유동성 필터 포함, n=1623) 기준이다.

## ① 손절폭과 EV — 전제가 재현되지 않음

사용자가 제시한 전제: "눌림목에서 손절≤5%만 남기면 EV 0.172→0.145로 떨어진다."
이번 측정으로 재현을 시도했으나 **재현되지 않았고, 오히려 방향이 반대로
나왔다.**

### 눌림목 재측정 (n=1623, 20개 체크포인트, 저유동성 필터 포함 최종본)

| | n | EV(R) | 손절률 | 도달률(2R) |
|---|---|---|---|---|
| 전체 | 1623 | 0.291 | 56.9% | 43.0% |
| 손절≤5% | 1371 | **0.300** | 56.7% | 43.3% |
| 손절 5%+ | 252 | **0.246** | 57.9% | 41.3% |

타이트한 쪽이 오히려 근소하게 우세 — 사용자가 인용한 방향과 반대다. 전체 EV
자체도 기존 문서치(`all_tabs_common_yardstick_investigation.md`의 0.172)와
다르다(0.291) — "기준선 불일치 조사" 절에서 원인을 특정하려 했으나 실패했고,
재현 가능성을 근거로 이번 수치를 채택했다(위 참고). "0.172→0.145"라는 조합
자체는 `docs/` 어디에도 기록이 없었다(grep 확인) — 아마 스캐너 화면에서 직접
토글해본 단발 스냅샷이었을 가능성이 높고, 그렇다면 표본이 훨씬 작아(하루치,
수십 건) 노이즈에 취약했을 것.

5개 탭 중 "타이트가 나쁘다"는 방향은 추세전환 하나뿐이고, 나머지는 무차이거나
오히려 타이트가 우세하다. **"손절 좁음=나쁜 신호"라는 단일 방향 결론은 전
탭은커녕 눌림목 하나에서도 성립하지 않는다** — 그때그때 다르다는 것 자체가
결론이다.

### 결론 및 반영

손절폭이 진입 품질과 안정적으로 연동되지 않는다는 것(방향이 탭·시점마다
바뀜)이 오히려 "배지는 포지션 크기 결정용이지 품질 신호가 아니다"라는 원래
문제의식을 더 강하게 뒷받침한다 — 다만 그 근거로 특정 방향("좁으면 나쁘다")을
못박는 대신 "방향 자체가 불안정하다"로 문구를 정정해서 반영했다.

- **필터/정렬 자체는 유지** — narrow가 나쁘다는 근거가 없고(오히려 3/5 탭에서
  우세), 포지션 사이징 목적 자체는 여전히 유효한 사용처이기 때문에 제거하지
  않음.
- **배지 툴팁**(`riskTierBadge()`, static/index.html): "포지션 크기 결정용 —
  좁다고 좋은 게 아님" + "전 탭 실측 결과 손절폭과 EV의 관계는 탭·시점마다
  방향이 다름" 명시.
- **인라인 안내줄** (신규, `#stopWidthWarnBanner`): 눌림목 탭에서 🔵필터나
  손절좁은순 정렬을 켜면 노출. 특정 방향을 단정하지 않고 최신 실측치(0.295 vs
  0.240)와 "방향이 고정돼 있지 않다"는 문구로 구성.

좋다"는 신호는 충분히 전달되고, 필터 여부는 사용자 선택으로 남기는 쪽이
스캐너의 탐색 기능을 해치지 않는다고 판단.

## ③ 눌림목 확인 후 진입 측정 — 돌파임박과 같은 패턴 재확인, 더 강하게

`docs/imminent_stop_entry_investigation.md` 3절의 방법론을 눌림목에 적용.

**정의** (돌파임박과 달리 손절 정의는 그대로 두고 진입 타이밍만 변수화 —
사용자 요청 범위):
- **안A(현행)**: 진입=신호일 종가, 손절=`analyze()`가 실제 계산하는 구조적
  손절(그대로).
- **안C'**: 신호일 다음 1~3봉 내 첫 번째로 "종가가 신호일 고가 초과 **+**
  그날 거래량이 트레일링 50일 평균의 1.5배 이상"을 만족하는 봉에서 진입
  (진입가=신호일 고가 레벨, 안C의 "고가 레벨 진입" 관례를 그대로 따름). 3봉
  내 미충족이면 미진입. 손절은 안A와 동일(재정의 안 함).
- **안D'(시점매칭 대조군)**: 안C'가 실제 진입한 그 봉에, 조건 확인 없이 그
  봉의 종가로 무조건 진입. 손절은 안A/안C'와 동일. n·타이밍이 안C'와 완전히
  같음 — "같은 날 진입해도 조건 확인 없이 종가로 사면 어떻게 되는가"만 분리.

### 결과 (n=1623, 저유동성 필터 포함 최종본)

| | 진입률 | 손절률 | 도달률(2R) | EV(R) |
|---|---|---|---|---|
| 안A 전체 | 100% | 56.9% | 43.0% | 0.291 |
| 안C' 진입분(n=261) | 16.1% | **35.6%** | **64.0%** | **0.923** |
| 안D' 진입분(같은 n·시점, 무조건 진입) | 16.1%(=C'와 동일) | 54.4% | 40.6% | 0.268 |
| 하이브리드(미진입=안A로 대체, n=1623 전체) | 100% | 58.5% | 41.3% | **0.242** |

### 해석

1. **안C' vs 안D' — 이번엔 필터 자체의 순수 효과도 크다.** 돌파임박에서는
   D'-와인 매칭(3.3절)에서 순수 필터 효과가 +4.3%p로 작았는데(대부분의 값이
   "확인 전엔 안 산다"는 시점/규율 효과), 눌림목은 **같은 날·같은 진입가
   기준으로도** C'(0.923R)가 D'(0.268R)를 큰 폭으로 앞선다. 거래량 1.5배+
   고가돌파 조건 자체가 실질 정보를 담고 있다는 뜻 — 돌파임박보다 조건-자체
   효과가 뚜렷하다.
2. **하이브리드(0.242R) < 안A 전체(0.291R) — 돌파임박과 같은 역설이 재현.**
   미진입 83.9%(1362건)에 안A를 채워 넣으면 역산 EV는 약 0.112R로, 안A
   전체 평균(0.291R)보다 한참 낮고 확인분(0.923R)과는 비교가 안 됨. "놓치기
   아까워서 안A로라도 채워 넣는" 시도는 여기서도 역효과 — 확인 안 되는
   84%가 안A로 진입해도 평범한(오히려 평균 이하인) 자리라는 뜻.
3. **결론**: 돌파임박의 "확인 전엔 진입하지 않는다" 규율이 눌림목에도 그대로
   적용 가능하고, 오히려 조건 자체의 순수 효과(C' vs D')는 더 크게 나온다.
   다만 진입률이 16.1%로 낮아(돌파임박 19.4%와 비슷한 수준) 전체 안A 자리를
   대체하긴 어렵고, 안A 위에 "확인되면 더 강하게 들어간다"는 보조 신호로
   쓰는 게 맞는 형태 — 돌파임박에 이미 있는 일지 관찰 트리거 배지(v5.44,
   등록일 고가/필요 거래량 필드)와 같은 패턴을 눌림목에도 붙일 수 있다는
   뜻이지만, 이번 요청은 측정까지였으므로 UI 구현은 하지 않고 다음 라운드
   후보로 남긴다.
