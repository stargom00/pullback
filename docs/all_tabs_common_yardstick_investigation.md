## 방법론

- **2R 레이스**: 진입=신호일 종가(또는 모드별 진입가), 손절=모드 자체 `stop` 필드, 목표=진입+2×(진입-손절), 최대 60봉까지 레이스. 결과 ∈ {손절, 도달, 미결, 데이터부족}. `EV_R = (도달/nv)×2 + (손절/nv)×(-1)`, `nv`는 데이터부족만 제외.
- **시점매칭 대조군**: 같은 시장, 같은 상대 체크포인트(`off`=시리즈 끝에서 거래일 수), 무작위 종목을 뽑아 동일 레이스를 돌려 비교.
- **체크포인트**: `off=60..250` (10 간격, 20개 지점) 전체 유니버스에 대해 반복 — 스냅샷 하루가 아니라 다수 시점 평균.
- **일평균 히트 수**: `n_hits / 체크포인트 수(20)`로 근사 — EV가 높아도 하루 1건이면 못 쓰고, EV가 낮아도 하루 50건이면 그 안에서 다시 고를 수 있다는 이유로 항상 병기.

## Script F — 슈퍼대장 안1 buy_zone 터치율 검증 (생존편향 재확인)

D의 안1 EV(1.22)는 "신호 즉시 buy_zone 진입"을 가정한 수치였고, 어제 안C에서 겪은 것과 같은 함정(터치 못 한 신호가 통계에서 빠짐)이 아닌지 확인 필요 — 사용자 명시적 게이트: "이거 통과하면 카드에 붙이고, 아니면 재설계."

- N봉 내 buy_zone 터치율: 5봉 49.9% / 10봉 56.1% / 20봉 63.6% / **60봉 72.1%** (즉, 60봉 내내 못 만나는 신호가 27.9%)
- 60봉 내 미터치 종목의 운명: 최대상승 중앙값 **+75.4%**, +15% 터치율 **99.2%** — buy_zone까지 기다리다가 못 만나는 종목일수록 오히려 이미 크게 갔던 종목이었다는 뜻(대기=최고 수익 기회를 놓치는 구조).
- 터치한 것만의 실제 EV: **0.361** (D의 1.22와 크게 다름 — 즉시체결 가정이 EV를 3배 이상 과대평가했음)
- 하이브리드 EV(미터치=진입없음=0R 포함 전체): **0.26**

**결론: 안1은 게이트를 통과하지 못함.** buy_zone 대기 진입 설계는 안C와 동일한 생존편향 함정이었다. 카드에 붙이지 않음 — 재설계 필요(다음 라운드 논의 대상).

과반인 탭은 눌림목 하나뿐. 눌림목 🔴는 사실상 0%(2건)로, 2항목 체제에서 "warn 2개=🔴" 조건이 거의 안 걸리는 게 확인됨.

### 검토했다가 기각한 안 — 비율 기반 판정 규칙

"전부 ok=🟢, 활성 항목의 절반 이상 warn=🔴, 나머지=🟡"(항목 수에 비례해 danger 문턱을 낮추는 안, 예: 2항목이면 warn 1개=🔴)을 검증. 결과: **🟢의 정의(활성 항목 전부 ok)는 두 규칙에서 완전히 동일**하기 때문에 이 규칙은 🟢 비율을 전혀 바꾸지 못함 — 눌림목 🟢은 58.0%로 그대로였고, 예전 🟡(748건)이 통째로 🔴(750건)로 옮겨갈 뿐이었다. n=3 탭(돌파임박/추세전환/돌파)은 `ceil(3/2)=2`로 기존 임계값과 같아 분포 자체가 무변화. **폐기.**

### 근본 원인 — 리스크 항목의 탭별 통과율 전수 조사

리스크뿐 아니라 4항목 전체를 5개 탭에서 통과율(ok 비율) 전수 조사(`item_pass_rates_all5.py`, Script A 원본 히트 재활용):

| 탭 | 거래량 ok% | RS ok% | 리스크 ok% | AVWAP ok% |
|---|---|---|---|---|
| 눌림목 | 49.3% | 58.5% | **99.4%** 🚩 | 73.3% |
| 돌파임박 | 50.1% | 63.2% | **97.1%** 🚩 | 61.7% |
| 추세전환 | 36.7% | 25.6% | 71.9% | 61.4% |
| 돌파 | **100.0%** 🚩 | 68.6% | **99.2%** 🚩 | 38.6% |
| 박스돌파 | **100.0%** 🚩 | 67.2% | **98.3%** 🚩 | 27.8% |

🚩 = 90% 이상(0비트 체크 후보 — 어제 손익비 100% 통과로 제거했던 것과 같은 유형). **리스크는 추세전환(71.9%) 한 곳만 실제 변별력이 있고 나머지 4개 탭 전부 90%를 훌쩍 넘는다.** 리스크의 손절폭 자체가 각 탭 설계상 이미 좁게 형성돼(눌림목/돌파임박/돌파/박스돌파는 근접 피벗 기준이라 risk_pct 분포가 애초에 12%/8% 한도 밑에 몰림) 통과 못 하는 경우가 거의 없기 때문.

**반영**: 90% 이상인 4개 탭(눌림목/돌파임박/돌파/박스돌파)의 리스크 항목을 참고용으로 격하. 추세전환은 유지.

- 눌림목: `['rs']` — 이미 거래량·AVWAP 제외 상태라 리스크까지 빠지면 **RS 단일 판정**만 남음.

- 돌파: `['vol', 'avwap']`

재확인한 🟢/🟡/🔴 (리스크 격하 반영 후): 눌림목 58.5%(무변화, 리스크가 애초에 거의 걸러낸 게 없었으니 당연함) / 돌파임박 38.8% / 추세전환 9.6%(무변화) / 돌파 38.6%(무변화) / 박스돌파 17.0%. **눌림목만 여전히 과반**이지만, 이제 그 이유가 "리스크·AVWAP·거래량이 판정에 안 쓰이는데 안 쓰인다는 표시가 없어서"가 아니라 "RS 단일 기준으로 판정하며 그렇게 나온 결과"임을 화면에 명시(아래).

### 발견 — "0비트"가 아니라 "0건"

가설은 "필드는 있는데 통과율 100%(0비트)"였지만(예: 슈퍼대장은 RS≥95라 이미 다 통과할 것) 실제로는 **필드 자체가 없어서 통과율 0%** — 정반대였다.

- **주도주만**(rs·(vol_mult|vol_ratio)·rr·risk_pct 4개 다 필요): 대장후보(rr·risk_pct 없음)/슈퍼대장(거래량 필드 자체가 없음 — v5.55로 risk_pct는 생겼지만 volOk가 항상 false)/급등(rr·risk_pct 없음) 3개 탭은 필드 부재로 클릭하면 **항상 0건**.
- **적격만**(`bear_ok`): `badge_fields()`를 호출하는 4곳(눌림목/돌파/돌파임박/패턴, +강한피벗은 돌파임박 상속)에만 존재 — 추세전환/대장후보/슈퍼대장/박스돌파/급등 5개 탭은 **항상 0건**.
- **손절좁은순**: `risk_pct` 없는 탭(대장후보/급등/붕괴/Stage2/IBD9/실적우수)에서는 전부 999 동점이라 정렬해도 순서 안 바뀜(정렬은 되지만 무의미).
- **매집순**: 코드 자체가 `mode==='pattern'`으로 게이트돼 있어 다른 탭에선 항상 no-op. 패턴 탭 안에서도 급등매집 서브패턴에만 `accum_score`가 채워짐(나머지는 의도적으로 맨 뒤 — 툴팁에 이미 고지됨, 문제 아님).

### 반영

버튼 표시 여부와 필터 적용 조건을 **같은 Set**으로 통일(따로 관리하면 또 어긋날 수 있어 `RISK_TIER_MODES` 패턴을 그대로 재사용):
- `STRICT_MODE_VALID` = {눌림목, 추세전환, 돌파, 돌파임박, 박스돌파, 패턴, 강한피벗} — 주도주만 버튼·필터 공용.
- `BEAR_OK_VALID` = {눌림목, 돌파, 돌파임박, 패턴, 강한피벗} — 적격만 버튼·필터 공용.
- `ACCUM_SORT_VALID` = {패턴} — 매집순 버튼·필터 공용.
- 손절좁은순은 기존 `RISK_TIER_MODES`를 그대로 재사용(같은 `risk_pct` 의존이라 새 Set 안 만듦).
- 필드가 없는 탭에서는 해당 버튼을 `display:none`으로 숨김. `hideFilterButtonsIfNotApplicable()`을 `load()` 진입 시점과 탭 클릭 핸들러(journal은 `load()`를 안 타서 별도 호출 필요) 양쪽에서 호출해 인버스/섹터/마감정리/일지로 전환할 때도 이전 탭의 버튼이 남아있지 않게 함.

## 미반영(다음 라운드 대상)

- 눌림목 RS 컷 인상(90→95, 🟢 58%→23.4%) — EV가 구간별로 비단조적(93~95에서 급락)이라 보류. 표본을 늘려 재검증하거나, RS 절대 컷 대신 다른 접근(상대 백분위 등)을 고려할지 판단 필요.
