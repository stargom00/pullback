# 거래대금 상위 종목 테마·자금흐름 분석 프롬프트

아래는 특정 주식시장의 *거래대금 상위 종목 순위, 티커/종목명, 등락률* 데이터다.
단순 업종 분류가 아니라 **현재 시장에서 실제로 돈이 몰리는 테마와 자금 이동**을 분석해줘.

## 1. 시장·거래일 확인
입력 데이터를 보고 먼저 시장과 현지 거래일을 판단한다.
* 한국 → KOSPI / KOSDAQ
* 미국 → NYSE / Nasdaq 등
한국시간과 미국 현지 거래일이 다르면 둘 다 명시한다.

## 2. 모든 종목을 하나의 주도 테마로 분류
입력된 모든 종목을 *중복 없이 반드시 한 곳에만* 분류한다.
분류 기준은 단순 업종보다:
> *현재 시장에서 실제 주가를 움직이는 핵심 사업·테마*
를 우선한다. 다른 사업 성격은 괄호나 세부 분류로만 표시한다.
처음 보는 종목, 신규 상장, 스핀오프, 티커 변경 종목은 추측하지 말고 현재 사업을 확인한 뒤 분류한다.
기본 테마는 시장에 맞게 자동 구성하며, 필요하면 신규 테마를 추가한다.

### 예시
미국: AI 플랫폼·빅테크 / AI 반도체·컴퓨팅·ASIC / 메모리·스토리지 / 반도체 장비·테스트 / AI 서버 / 네트워크 장비 / 광통신·포토닉스 / 인터커넥트 / 네오클라우드·AI 데이터센터 / 데이터센터 전력·냉각 / 엔터프라이즈 소프트웨어·AI 앱 / 사이버보안 / 금융·핀테크·크립토 / 헬스케어 / 소비 / 에너지·원자재 / 산업재·방산·우주
한국: HBM·메모리 / 반도체 장비·소부장·패키징 / PCB·기판·유리기판 / 전력기기·원전 / 조선·방산·로봇 / 2차전지·ESS / 바이오·제약 / 증권·은행 / 자동차 / 화장품·중국소비 / 인터넷·게임·AI 소프트웨어
*종목 하나 때문에 억지로 새 테마를 만들지 않는다.*

## 3. AI는 반드시 밸류체인별로 분리
`AI 관련주`라고 한꺼번에 묶지 않는다. 가능하면:
> 플랫폼 → GPU·ASIC → 메모리 → 장비 → 서버 → 네트워크 → 인터커넥트 → 광통신 → 네오클라우드 → 전력·냉각 → 인프라 시공 → 소프트웨어 → 보안
으로 구분한다. 같은 AI라도 하위 밸류체인이 다르게 움직이면 반드시 그 차이를 설명한다.

## 4. 하나의 통합 표로 출력
| 핵심 테마·섹터 | 세부 분류 | 종목 및 등락률 | 종목 수 | 흐름 판단 |
규칙:
* 입력 등락률은 그대로 사용
* 같은 테마에서는 거래대금 순위순
* 모든 종목 포함
* 중복 금지
흐름 판단은 아래 5개만 사용: *강세 / 상대강세 / 혼조 / 상대약세 / 약세*
판단 기준: 상승·하락 종목 비율 / 상승·하락 폭 / 핵심 종목 방향 / 테마 전체 확산도
한 종목 급등만으로 테마 전체를 강세로 판단하지 않는다.

## 5. 시장 구조 분석
표 아래에서 반드시 다음을 분석한다.
### 가장 강한 테마 3개
* 대표 종목 / 상승 확산도 / 개별 이슈인지 테마 전체 움직임인지
### 가장 약한 테마 3개
### 자금 이동
가능하면:
> A에서 자금 이탈 → B로 이동 → C까지 확산
형태로 설명한다.
이전 거래일 데이터가 있다면:
| 테마 | 이전 | 오늘 | 변화 |
형태로 비교하고, 강→약 / 약→강 / 연속 강세·약세 / 신규 등장 테마 / 기존 주도 테마 이탈을 찾아낸다.
하루 움직임만으로 중기 주도권 변화를 단정하지 말고 **당일 자금 이동**으로 표현한다.

## 6. 신규 종목·급등락 종목 확인
기존에 잘 보이지 않던 종목이나 **±10% 이상 움직인 종목**은 원인을 확인한다. 특히 ±20% 이상은 반드시 확인한다.
다음을 구분한다: 실적·가이던스 / M&A / 정책·규제 / 수주 / 임상 / 신규 상장·락업 / 숏스퀴즈 / 초소형주 특수 움직임
초소형주 ±100% 이상 급등은 시장 전체 테마 분석에서 제외한다.
신규 종목군이 여러 개 함께 등장하면: *지속 관찰 가치 높음 / 추가 확인 필요 / 개별 이슈* 중 하나로 평가한다.

## 7. 지수와 시장 내부 흐름 비교
해당 시장 대표 지수를 확인한다.
* 미국: S&P500 / Nasdaq / Dow / Russell2000
* 한국: KOSPI / KOSDAQ
그리고 입력 종목의 상승/하락/보합 종목 수, 상승 비율, 가능하면 평균·중앙값을 계산한다.
예:
> 지수 상승 + 상승 종목 적음 → 좁은 상승
> 지수 하락 + 상승 종목 많음 → 대형주 약세 속 내부 순환
처럼 해석한다.

## 8. 뉴스는 정확히 3개
분석 순서는 반드시:
> *가격·거래대금 분석 → 자금 이동 판단 → 뉴스로 검증*
순으로 한다.
해당 현지 거래일 또는 직전 장 마감 이후 뉴스 중 *시장 설명력이 가장 큰 3개만* 선정한다.
우선순위: 매크로·금리·물가·고용 / 정책·규제 / 지정학 / 산업 공급·수요 변화 / 주요 실적·CAPEX·수주
신뢰도 높은 출처와 1차 자료를 우선한다.
뉴스 형식:
### 1. 뉴스 제목
* *핵심 내용:*
* *시장 연결:*
* *관련 종목·테마:*
* *출처:*
확실한 인과관계가 아니면 **"영향을 준 것으로 해석된다"**고 표현한다.

# 최종 출력 순서
1. 분석 시장·현지 거래일
2. 통합 테마 분류표
3. 강한 테마 3개
4. 약한 테마 3개
5. 이전 대비 변화 및 자금 이동
6. 주요 밸류체인 내부 흐름
7. 신규 종목군·급등락 종목
8. 지수 vs 시장 내부 흐름
9. 핵심 뉴스 정확히 3개
10. *오늘 시장 최종 한 문장*
11. 데이터 검증
12. 기계 판독용 요약 JSON

## 12. 기계 판독용 요약 (반드시 맨 마지막, 11번 뒤에 추가)

전체 리포트를 다 쓴 뒤 **맨 마지막에** 아래 형식의 JSON 코드블록을 정확히
하나만 추가한다. 텔레그램 봇이 이 블록만 파싱해 요약 알림을 보내므로
형식을 반드시 지킨다:

```json
{
  "strong_themes": ["테마명(간단근거)", "테마명(간단근거)", "테마명(간단근거)"],
  "weak_themes": ["테마명(간단근거)", "테마명(간단근거)", "테마명(간단근거)"],
  "final_sentence": "10번 항목의 오늘 시장 최종 한 문장을 그대로 반복"
}
```

* `strong_themes`/`weak_themes`는 3번/4번에서 고른 테마와 반드시 동일한
  3개(순서도 동일)여야 한다.
* 간단근거는 "종목수+확산단계" 형태로 간결하게 (예: "8종목 확산(본격)").
* 이 JSON 코드블록 뒤에는 어떤 텍스트도 추가하지 않는다.

# 데이터 검증
마지막에 반드시 확인한다.
* 입력 종목 수 / 분류 완료 종목 수 / 중복 종목 수 / 누락 종목 / 임의 추가 종목 / 상승·하락·보합 종목 수
*입력 종목 수 = 분류 완료 종목 수* / *중복·누락·임의 추가 = 0*

# 핵심 원칙
* 업종보다 **실제 주가 동인과 돈의 흐름**을 본다.
* 테마는 반드시 **확산도**를 본다.
* AI는 밸류체인별로 세분화한다.
* 개별 급등주와 테마 상승을 구분한다.
* 지수와 시장 내부 흐름을 따로 본다.
* 뉴스에 움직임을 억지로 끼워 맞추지 않는다.
* 미래를 예측하기보다 *현재 어디에서 돈이 빠지고 어디로 들어가는지* 설명한다.

# 추가 지시 — 지속성·확산 데이터 활용 (2026-08-26, money_flow.py 연동)

입력 데이터(JSON)에는 원 프롬프트가 요구하는 순위·등락률·거래대금 외에
`money_flow.py`가 미리 계산해둔 두 필드가 테마별로 함께 들어온다. 이
둘을 **"5. 자금 이동" 판단의 핵심 근거로 우선 사용**할 것 — 표만 보고
매번 새로 추론하지 말고, 이미 계산된 값을 그대로 인용한다.

* **`streak_periods`**: 그 테마가 거래대금 점유율 상위 10위 이내에
  연속으로 든 실행 회차 수(이번 실행 포함). **주의: 이 리포트는 2026-09
  부터 매일이 아니라 주 1회 실행된다** — `streak_unit` 필드가 그 회차의
  실제 단위를 알려주며, 지금은 항상 `"week"`다(즉 `streak_periods=3`이면
  "3일 연속"이 아니라 "3주 연속"이라는 뜻). 서술할 때 반드시 `streak_unit`
  값 그대로 단위를 붙여라(`"week"`→"주", 다른 값이 오면 그 값을 그대로
  단위처럼 사용) — "일"을 임의로 쓰지 말 것. `in_streak_rank`가 `false`면
  이번 실행 시점 상위 10위 밖 — streak가 끊긴 것이다.
  - `streak_periods`가 여러 회차 연속으로 유지·증가 중인 테마는 "연속
    강세"로 표현하고, 이번 실행에서만 반짝 오른 테마(streak_periods=1,
    특히 `in_streak_rank`가 직전 실행엔 false였다가 이번에만 true)와
    명확히 구분해서 서술한다. 실행 간격이 1주라는 점을 고려해 "최근
    한 주간" 같은 표현을 쓰고 "어제"/"하루" 같은 일 단위 표현은 쓰지
    않는다.
  - "5. 자금 이동"의 "강→약 / 약→강 / 연속 강세·약세 / 신규 등장 테마 /
    기존 주도 테마 이탈" 판단은 반드시 `streak_periods`(+`streak_unit`)/
    `in_streak_rank` 수치를 근거로 제시한다(추측 금지).
* **`stage`**(테마 내부 확산 단계, `leaderboard`의 대장주/2등주/3등주
  기준 규칙 판정): `초기(대장주만)` / `확산(본격)` / `말기 경계(후발주만)`
  / `비확산` / `표본부족`(테마 내 종목 2개 미만이라 판단 불가) 중 하나.
  - **"확산(본격)"은 그 테마의 자금 유입이 가장 신뢰할 만한 신호**다 —
    대장주와 후발주(2·3등주)가 동시에 오른다는 뜻이라, 개별 종목 이슈가
    아니라 테마 전체로 자금이 퍼지고 있다는 근거로 우선 인용한다.
  - "초기(대장주만)"는 아직 확산 전 — "강한 테마 3개"에 넣더라도 "대장주
    단독 상승, 후발주 미동" 임을 반드시 함께 명시한다(4. 표의 흐름
    판단에서 "한 종목 급등만으로 테마 전체를 강세로 판단하지 않는다"는
    원칙과 직결).
  - "말기 경계(후발주만)"는 대장주가 쉬고 후발주만 오르는 상태 — 원
    프롬프트가 요구하는 "확산도" 판단에 쓰되, 강세 테마로 소개할 때도
    "경계 신호"로 같이 언급한다.
* streak와 stage를 함께 보고 최상급 신호(예: 여러 회차 연속 상위 +
  이번 실행 확산(본격))는 "가장 강한 테마 3개" 절에서 다른 테마보다
  우선 배치하고 그 근거(연속 N`streak_unit`(현재는 "주") + 확산 단계)를
  명시한다.

이 두 필드는 `money_flow.py`가 결정론적 규칙으로 미리 계산한 값이며
진입 신호가 아니다 — "돈이 어디서 빠지고 어디로 들어가는지 설명"하는
이 프롬프트의 핵심 원칙에 맞게 참고용 근거로만 쓴다.
